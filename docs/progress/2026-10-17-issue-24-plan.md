- Scope revision 1、区分C。元IssueのAC-1〜7・INVAR-1〜3を維持する。既存の認証・CLI・Run実行契約と料金設定を使い、新しいLLM接続や中央モデル台帳を要求しない。
- 目的: CLIが機械的に報告したモデル・数量をRunへ対応付け、欠測・遅着・費用の種類と根拠を共通画面から確認できるようにする。
- 対象外: 全CLI・全契約・全内部呼出しの完全計測、認証やゲートウェイの強制変更、時間帯・APIキーによる推測帰属、LLMの文章による数量申告。

## 採用構成の調査

WindowsのCodex `0.162.1`、Claude Code `2.1.300`で、ツールを使わず短い応答だけを返す新規セッションと、その同じセッションの再利用を実行した。いずれも終了0。資格情報は元CLIに任せ、取得した記録から数量・モデル・識別子だけを抽出した。

Codexの`turn.completed.usage`は再利用時に過去分を含んだ。新規は入力24819・出力5、再利用後は入力49661・出力10だった。標準出力には実モデル名がない。今回作成したthreadだけを`state_5.sqlite`のID索引で照合し、対応するrolloutの`turn_context.model`で`gpt-6.1-sol`を確認した。モデル名をLLMへ質問して得た値ではない。

Claude Codeの`result.modelUsage`は`claude-opus-5-5`のモデル別数量を持ち、再利用後は同じsessionの過去分を含んだ。`total_cost_usd`とモデル別`costUSD`はCLIの単価表による参考推定額で、実支払額とは扱わない。主ループの`usage`と、子処理を含む`modelUsage`の範囲を区別する。

根拠は[Codex非対話実行](https://developers.openai.com/codex/non-interactive-mode)と[Claude Codeの費用・数量](https://code.claude.com/docs/en/agent-sdk/cost-tracking)、上記の実測。公式仕様と実測の違いや取得不可の項目を接続能力へ明記する。元CLIの全履歴はサーバーへ送らない。

調査は、採用版・イベント源・安定ID・累積範囲・取得できない内訳を記録し、固定fixtureと実接続で対応付けを検証した時点で終了する。隠れた子処理や内部再試行の完全取得を追加条件にしない。

## 最終実装と境界

既存UsageRecord・料金版・費用評価・重複排除へ接続する。別の費用正本や独自の合算処理は追加しない。Run報告とは独立した計測送信経路を使い、計測の失敗で終了報告を塞がない。端末側は既存の暗号化journalを使い、未送信は受付まで保持して同じIDで再送する。保存済みの計測と元記録参照は既存の無期限保持方針に従う。

CLIの構造化イベントと、当該sessionに限定したローカルの機械記録を使う。全プロジェクトの履歴巡回、全文対話の追加保存・送信は行わない。新規/継続の境界や実モデルが証明できない場合は、その項目を未取得・未帰属にする。設定したモデル名を実モデルへ読み替えない。子処理・再試行の範囲を能力に記録する。

共有の保存は既存mutation/receiptと現在認可を使う。対象Run・割当世代・端末を送信ごとに照合し、Run終了後も許可が有効なら遅着を受ける。利用量の取得元・帰属・参照へRunと入力の現在権限を反映する。料金版の変更や評価の再計算は既存の明示操作を維持する。CLIの参考推定額と実請求額、定額契約とAPI換算額を分ける。

一覧は選んだRunの索引付きページとする。Workspace全体の最新計測を先に作ってから絞る方式は使わず、必要な索引は新規migrationで追加する。既存migration 001〜019と既存CLI/Runの出力形式・意味は変更しない。共通化が必要な保存処理は利用側も切り替え、二重経路を残さない。

予定pathは`apps/client/src-tauri/src/runner/`の収集・暗号化保留・再送、`apps/server/internal/usage/`の共通保存とRun別取得、`apps/server/internal/runs/`の報告認可、共通Run詳細の数量・費用表示、対応する単体/PG/ネイティブ統合fixtureと文書。元Issueの条件と調査で確定した能力以外の製品判断が必要なら、影響のない作業を進めながら確認する。

必要な局所テスト・PG・desktop検査と固定成果物の独立検品、最終head CI・マージ後照合で完了を判定する。Windowsアプリのログイン・終了・スリープと人の初見操作は繰り返さない。共通UIの一回の確認を再利用する。
