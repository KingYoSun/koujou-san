- 基準main: `fbb0637ff4f9de825a37a4dc808f7495517f6758`。#20はPR #53の全CI・独立検品・マージ後tree一致でClose済み。

- 対象は検品の固定入力・派生契約・分離情報・条件別の結果・証拠と有効性。既存Run、ContextManifest、権限、Runner、工程と保存を使う。
- 実機操作は必要最小限とする。GUIの起動・認証・画面終了・スリープを再確認しない。CLIと別保存域・登録端末の受け渡しは可能な限り自動化する。

## 完了範囲

InspectionRunとHumanReviewRunを共通Runの派生として扱い、対象・条件・入力・期待する判定形式を固定する。検品専用の実行エンジンは作らない。契約検品では選択したContextを使い、初見検品では明示的に無注入を設定する。実装の会話や成功宣言、自己評価、全Workspaceの文書を自動で入力へ追加しない。

会話、作業場所、読取り・書込み、外部接続、基準、Contextの分離を、宣言・ログ等で確認した範囲・環境で強制した範囲へ分けて記録する。CLI名や新プロセスだけで完全分離を保証しない。必須条件を満たさない接続は開始させず、条件を変える場合は新しい版として明示する。未確認の能力を強制済みへ格上げしない。

条件別の判定と証拠を記録し、終了コード、原出力、形式の妥当性、内容の受入れを区別する。自然文から合否を推測して原出力を置き換えない。差分検品は再利用元、変更範囲、影響確認と未確認を持つ。人の例外判断は、元のFAILやINCONCLUSIVEを保持した別の判断として残す。

対象・基準・必須入力の変更を追い、旧判定を新しい対象のPASSとして再利用しない。外部の証拠所在が失効しても、過去の判定と現在の再確認可能性を別に示す。記録は既に承認された無期限の履歴方針に従う。成果物全量の中央コピー、未承認の保持期間や全検品共通の思想は導入しない。

新しい一覧は検品対象の索引とページを使い、Context全件・原出力全件・全履歴を通常操作で走査しない。対象成果物は既存の固定URI・commit・snapshot/digestを使い、端末のパスやCLIの認証情報を共有設定へ写さない。

## 有限な判定条件

| 条件 | 対象と期待結果 | 判定方法 |
| --- | --- | --- |
| AC-1 | 契約検品の選択注入と初見検品の無注入を固定し、対象・条件版・Manifest・実入力が一致。実装会話と自己評価の自動継承なし | 二つの固定検品と合成の非注入マーカーを、サーバー・CLI入力・原出力で照合 |
| AC-2 | 二つの登録端末と別の保存域・接続で同じ固定成果物を検品し、端末パス・認証・内部履歴・未commitファイルを暗黙に渡さない | 所有する固定リポジトリと二Runnerの受渡し、元checkout不変、CLI入力・共有記録を照合。実施した環境を明記 |
| AC-3 | 分離の宣言・ログ確認・環境強制を区別し、必須条件の能力不足は開始しない | 足りる宣言と不足・未確認の各一例で、割当/起動境界と表示を確認 |
| AC-4 | 条件別の根拠・未確認を保存し、終了0のFAIL、不正形式、必須欠落、未実行、証拠不足をPASSにしない | 正常レポート一例と上記五つの不成立例を共通Run契約と照合。原出力を比較 |
| AC-5 | 対象・基準・必須入力を各一回変え、旧判定をStaleとして保持し、新しいInspectionRunへ関連付ける | 三つの変更と新Run・旧input/output・有効性を比較 |
| AC-6 | 差分検品に再利用元・変更範囲・影響確認を残し、根拠不足は未確認のまま | 一つの差分案件の十分な根拠と不足した根拠を比較 |
| AC-7 | 実機・人・AIコメント・実装者申告を区別し、対立と人の例外判断で元の判定を変更しない | 同じ対象の対立する二判定と一つの例外判断、別主体の拒否を照合 |
| AC-8 | 証拠の所在失効を現在の状態として表示し、元の判定履歴を保持する | 固定証拠の利用可から失効への一遷移と履歴・画面を比較 |
| INVAR-1 | 固定対象と条件の外側へ適合したと判定しない | 未指定条件を持つ結果の拒否・未確認を照合 |
| INVAR-2 | 推奨経路が工程と権限を変更しない | 未定義の開始を勧めるレポートで追加実行0 |
| INVAR-3 | 製品哲学は選択入力として扱い、全Runへ追加しない | 選択あり・なしの実入力と固定参照を比較 |

## 調査と実装の終了条件

CLIのセッション・設定・共有メモリ・資格情報・OS制限を、インストール済みの版と公式資料、固定入力で調べる。確認・強制できる範囲と未確認をADRへ記録したら方式調査を終える。ユーザーの認証情報の複製、保護設定の解除、新しい永続アクセスの作成は調査の前提にしない。

レポート形式は、編集可能な派生契約と固定commandで正常・不成立の例を受け渡し、原出力・決定的変換・別Runによる変換を区別できた時点で確定する。指定した条件・成果物だけを扱い、未知の不具合がないことの証明へ広げない。

予定pathは`internal/inspections`、新規migration、既存Run/Runner/Contextの必要な接続、共通検品画面、固定CLI fixtureとする。既存migrationや既存Runの保存形式を置き換えない。派生の入力・結果と分離条件の照合は共通の責務で実装し、同じ検証の複製を避ける。

## 検証と検品

純粋な契約検証、専用PGの固定案件、実Oryと必要なCLI受け渡しで条件を確認する。新しい画面は共通UIで一回の流れを確認し、既存のRun/Pause/ネイティブOS境界の証拠を再利用する。特定のモデルや物理環境で未確認の保証を、他環境の成功から補わない。

固定成果物とAC-1〜8・INVAR-1〜3を、実装会話を継承しない独立担当へ渡す。必要な検品・実際のPR CI・マージ後の内容一致を確認するまでCloseしない。判断が必要な受入条件・利用者体験・互換性の変更が見つかったら、その変更に依存する実装を止める。
