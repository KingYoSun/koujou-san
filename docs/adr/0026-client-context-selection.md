# 0026: クライアントによるContext選択と共通の版付き保存

- 状態: クライアント契約は採用。Gatewayの初期提供方式と本文ログはユーザー判断待ち。
- 日付: 2026-10-18。
- 根拠: Issue #26、設計書§6.10・6.11・12.4・14.3、[計画](../progress/2026-10-18-issue-26-plan.md)。

## 操作と保存

Context選択をRunにしない。Go APIは方針、操作、送信意図、原応答、質問回答、変更案、採用した選択を固定版として保存する。モデルへのHTTP要求とMCPのtoolループは、依頼者のクライアントが担当する。APIサーバーは担当クライアントの不在を肩代わりしない。

手動・提案・自動反映は同じ選択保存サービスを使う。現在権限、元版、手動の必須項目・順序・除外を確認し、既存のContext解決処理からRunを持たないManifestを確定する。通常のRun用Manifest保存APIは、従来どおりRun IDを必須とする。保存・採用でRunや実行要求を作らない。

初期反映方式は、検証済みの選択の自動反映とする。質問、未確認事項、元版競合、不完全な探索、権限や方針の変化があれば自動反映しない。原応答と案は、反映に失敗しても残す。画面の選択が処理中に編集されていた場合は、保存結果を知らせ、編集中の選択を上書きしない。

質問への回答と処理担当の引継ぎは依頼者本人に限定する。本人の別クライアントへ明示的に引き継げる。送信済みで結果不明の要求は、引継ぎ・再接続だけでは再送しない。送信意図の要求IDと固定版、receiptによって応答喪失を照合する。旧クライアントから届いた遅い原応答は記録しても自動反映しない。

## 件数と送信範囲

初期から膨大なContextを扱う。Workspace全体の本文・IDを先に取得せず、Scope、検索、関係探索、ページ継続、必要な固定文書の取得で候補を絞る。モデルへ公開する業務toolは`context_search / context_graph / context_get / context_resolve`の読取りに限定する。MCP Sampling、Run開始、Context編集のtoolはこのHostへ渡さない。

ADR 0010の送信禁止分類、現在権限、操作目的、明示したScopeと除外をサーバーで検証する。必須の固定参照と、検索で見つける候補の範囲を分ける。検索から直接の許可範囲を増やさない。複合Contextの取得とプレビューでは子要素まで検証し、除外IDや入力全文をモデル向けプレビューへ付けない。検品向けのHostは、当該操作の依頼と本人の回答だけから対話を組み、実装対話・自己評価・別操作の対話を復元しない。

通常の次ページを、探索打切りや投影遅延と区別する。検索・グラフの継続は、Context・所属・関係の変更で無効にする。操作や利用量の記録だけで、内容が変わっていない候補を反映待ちにしたり、ページ継続を無効にしたりしない。共有変更の索引付き範囲照合を使い、全Contextを走査しない。現在の認可は各要求で確認する。

変更可能な初期上限は、1操作につきモデル要求32回、MCP要求256回、600秒とする。明示再開でも累積要求数と期限をリセットしない。ScopeやWorkspace全体のContext件数を制限する値ではない。接続ごとの費用上限を指定でき、費用の欠測・未算定・参照不能は0にしない。

## 接続と資格情報

モデル接続はOpenAI互換の非ストリーミングHTTPを使い、tool要求と厳密なJSON出力を渡す。要求モデルと許可する実モデル名を固定し、応答の実モデル名を照合する。GatewayがHTTP 200で説明文を返しても、モデル・出力schemaの確認に失敗すれば選択として採用しない。接続設定の保存だけではモデルへ要求しない。

Webの接続用キーは画面内メモリだけに保持する。再読込後は再入力し、設定のメタデータだけを利用者・APIごとに保存する。Windowsでは利用者・APIごとにDPAPIで暗号化し、Context本文キャッシュ、通常API認証、MCP認証とは別の保存先を使う。接続先を変えた設定へ古いキーを流用せず、HTTPリダイレクトにも転送しない。

MCPは専用scopeとresourceを持つOAuth認証を使う。Webでは専用のHttpOnly cookieと同一Originの`/mcp/host`を使い、CSRFと現在の本人を確認してMCP bearerへ中継する。モデル要求をこの中継へ置かない。Windowsは同じPKCEエンジンを用途別の設定・保存先で使う。MCPプロトコル`2026-07-28`のstateless discovery、要求メタデータ、HTTP method/nameヘッダを共通Hostから送る。

モデルHTTPにはOry/MCPのtokenやcookie、Workspaceの操作handleを付けない。接続用キーをMCPや共有の操作記録へ保存しない。費用は操作IDに帰属させ、Runへ計上しない。モデル送信前に未確認の利用量を作り、応答後に同じ要求の観測として確定する。実モデルに対応する個別契約単価からの算定も、既存のusageサービスを使う。

## Gatewayの評価と残る判断

Manifest 6.28.9を固定して、tool、構造化出力、明示モデル、許可fallback、再試行、本文ログ無効、相関、再起動復旧を所有する上流HTTPで確認した。Autofix・telemetryを無効にした観測期間に、それらの送信先へのfetchはなかった。価格表などの外部取得はあった。実LLMの意味判断の品質、全期間・全通信方式の無通信を確認したとは扱わない。

同梱、標準サービスへの追加、本文ログの初期値は未確定である。依存と配布条件の確認結果、配置負担と観測の範囲は[Gateway評価](../progress/2026-10-18-issue-26-gateway-probe.md)へ記録する。判断前に標準構成へGatewayを追加しない。
