# 0024: CLIの機械記録からRun別の利用量を取得する

- 状態: 実装・受入検証中。
- 日付: 2026-10-17。
- 根拠: Issue #24、[計画](../progress/2026-10-17-issue-24-plan.md)、[既存の利用量と料金](0013-usage-pricing.md)。

## 取得元と境界

Windows Codex 0.162.1とClaude Code 2.1.300の構造化出力を採用する。LLMの回答本文は計測値として解析しない。版の照合がない接続・未採用版・通常CLIでも実行を続け、計測は取得不可とする。LLM非該当は明示設定で区別する。

Codexは`turn.completed.usage`から数量を得る。モデルを取得する接続では、実行ごとの一時的なループバックOTel出力を明示的に有効化する。受信側はsessionとmodelだけを保持し、メール・認証・プロンプト・ツール結果の属性を保持・送信しない。会話履歴を追加保存せず、既存接続の設定も自動変更しない。モデル取得を有効にした実行では、既存の外部OTel出力先をその実行だけ置き換えることを設定画面へ表示する。

Claude Codeは`result.modelUsage`のモデル別数量を使い、`costUSD`はCLIの参考推定額として保存する。途中取得を選んだ接続ではassistantの機械的なmessage IDで入力・cacheの重複を除き、placeholderである途中の出力数量は未取得にする。終了結果の累積値で同じ系列を更新し、途中値と合算しない。取得元の処理パイプライン外の補助呼出しは未取得とする。

再利用・forkの累積値は、今回のRunとの境界が確認できないため要確認にする。元の数量は参照できるが、確定したRun別集計や費用へ採用しない。Codexの子sessionや内訳が見えない内部処理も取得済みとはしない。モデル名・数量・取得範囲の不明を0へ置換しない。

## 保存と現在権限

既存のUsageRecord、coverage group、累積系列、料金版、費用評価を使う。任意の計測情報は後方互換なoptional metadataとして保存し、既存記録を移行しない。既存migration 001〜019は変更せず、Run別ページには016の索引を使う。

端末は既存の暗号化journalへ、計測専用の未送信queueと受付版を保存する。同じevent・operationで再送し、応答喪失時も試行内容を変えない。拒否された記録を保留したまま、別Runの送信へ進める。Runの原出力・終了報告とは別queueにして、計測の送信失敗でCLI結果を変えたり再起動したりしない。未送信は受付まで、保存した計測と参照は既存の無期限保持方針に従う。

サーバーは現在の端末・報告許可・Run割当世代・実行依頼者・固定入力の権限を保存transactionでも確認する。終了後の遅着は受け付けるが、他のRunや世代への付け替えは認めない。Usageの読取り・集計・費用評価にもRunと固定入力の現在権限を適用する。Runの状態・input・原出力・commandは更新しない。

## 共通画面と検証

選択したRunだけを索引付きページで取得し、モデル・数量・取得状態・元記録・料金版へ進める。Workspace全件の最新値を作ってからRunを絞る処理は追加しない。CLIの参考推定額、料金版による推定額、報告額、未算定を分け、定額契約とローカル実行を0支払と表示しない。料金設定と費用評価の明示操作は既存方針を維持する。

機械イベントのfixture、暗号化保留と再送、専用PG、実CLIと共通画面、固定成果物の独立検品で照合する。人による初見操作とOSの起動・認証・スリープを繰り返さない。
