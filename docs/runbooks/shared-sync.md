# 共有と下書きの確認

Workspaceを選び「コンテキスト」で対象を検索する。候補・Scope・関係はページで取得し、本文は開いた対象だけを読む。文書の構造、Scopeへの直接所属、入力する固定版の選択を分ける。操作の詳細は[Context編集](context-ui.md)を参照する。

本文や名前を変更すると端末の下書きになる。「下書きを共有版へ保存」を選ぶまで正本は変わらない。再接続しても自動送信しない。競合時は基準版・現在の共有版・下書きを比較し、明示的に再適用する。

「保存結果が未確認」は保存失敗の断定ではない。「同じ要求IDで保存結果を確認」で前回の操作を照合する。受付を確認した保存版と、現在取得した版を別に表示する。

## 保存と失効

Webの下書きと確定キャッシュは同一originのIndexedDB、WindowsはAPI接続先・User・WorkspaceごとのSQLiteに、DPAPIで保護したレコードを保存する。旧形式からの移行後は旧版アプリと混在させない。起動後は保存時点のデータを復元し、APIへ現在の権限と更新を照会する。切断中はキャッシュの時点と古い可能性を示す。

サインアウト・Workspace取得権限の失効を確認すると、対象の本文キャッシュと未送信下書きを削除する。対象だけの取得権限を失った場合も、その本文と下書きを削除する。通信断中は権限変更を確認できないため、最新権限を確認済みとは表示しない。

## APIと後続実装の接続

共通GUIは`POST /sync/workspaces/{workspace}/pull`の`watch`で、対象のkind/idと既知の版を最大100件ずつ照合する。変更した本文だけを取得する。

既存の同じAPIのsnapshot/changesは、取得位置、継続cursor、取得済みのkind/idを受け取る。取得済みIDは100件ずつ照合し、各照合の終端を同じthroughへ固定する。snapshotの基準位置もページ間で固定する。差分の履歴不足・不明cursorはsnapshotへ切り替える。取得位置・cursorを数値として比較せず、不透明な値として保持する。

`POST /sync/workspaces/{workspace}/reports`は担当Deviceだけが利用する。event_id・target_id・sequence・観測種別と、任意の論理artifact ID/版を送る。ID/版は英数字・`_`・`-`から成り、端末パスや自由なログ本文は渡さない。1/3/2の報告で欠落と遅着を照合できる。欠落が埋まっても実行結果は未確認のままとする。実Runの結果・Pause配送・CLIプロセスの照合は#16以降で接続する。

Context/所属の保存は既存`/contexts` APIを使う。下書きと結果不明の要求を区別し、送信前に同じ操作ID・前提版・内容を保存する。Run開始・割当変更・外部起票・pause回答を、この編集経路へ流さない。

## 検証

`pnpm run test:sync`は分離PGで同期・競合・履歴不足・報告の順序と現在認可を照合する。通常の`test`に共通UIエンジンの試験、`test:desktop`にDPAPIキャッシュの保存・復元・削除を含む。現行GUI・移行の方法と結果は[Issue #12の記録](../progress/2026-10-16-issue-12-evidence.md)、導入時の通知・実行報告は[Issue #8の記録](../progress/2026-10-15-issue-8-evidence.md)を参照する。

`scripts/sync-fault-proxy.mjs`はローカルの検証専用TLS中継で、標準APIの代わりには常設しない。APIの公開URLを8080のまま、待受だけを8081へ変更して起動し、中継を8080に置く。stdinの`offline / open / lose-next-write`でWindowsの通信断と保存直後の応答喪失を検証できる。ヘッダー・本文をログへ出さない。終了後は中継を停止し、APIの待受を8080へ戻す。
