# Runのモデル・利用量・費用

Workspaceの「作業と判断」でRunを選ぶと、「このRunのモデル・利用量・費用」を確認できる。表示種別を利用量・報告額・単価からの推定額・API料金換算額・配賦額から選び、固定した計測・評価・料金版の根拠を開く。次ページは50件ずつ取得する。

## 接続を設定する

WindowsのCLI設定にある「利用量の取得と契約」で、課金方式と個別契約の識別名を指定する。秘密値は入力しない。個別単価は既存の[料金設定](usage-pricing.md)を使う。設定の保存だけではCLIを起動しない。

初期の採用版はCodex `0.162.1`とClaude Code `2.1.300`。接続の版と実行programの`--version`を照合する。未採用版・未確認版・通常CLIは計測を取得不可として実行し、LLMを使わない接続は「LLM非該当」を明示する。

Codexは終了時の数量を取得する。「Codexのモデルを端末内で計測する」を有効にした接続では、Windows上で当該実行だけの一時的なOTel受信先を用意する。受信先は端末内で、sessionとmodelだけを保持する。この実行の外部OTel出力先は置き換わるため、外部監視を維持したい接続では有効化しない。認証・会話履歴の非保存設定は維持する。無効時や取得できない環境ではモデルを未取得にし、指定モデル名から推測しない。WSL内CLIのモデル取得は初期の検証対象外。

Claude Codeは終了時のモデル別数量を取得する。途中更新を選ぶと入力・cacheを暫定表示し、出力のplaceholderは計測値にしない。終了結果で同じ系列を更新する。`modelUsage`は子処理を含むCLIの処理パイプラインであり、範囲外の補助呼出しの消費は未取得。

## 計測状態と費用

「途中更新・暫定」「終了時取得」「一部取得」「取得不可」「LLM非該当」を区別する。数量のnullは未取得で、実測0とは異なる。cache・推論が親数量の内数であれば、その定義を表示する。

再利用・forkのセッション累計から今回の消費を切り分けられない記録は確認対象とし、通常の数量・費用表示へ採用しない。確定していない集計値を時間帯やAPIキーから補わない。原記録参照が未取得なら、取得済みの証拠とは扱わない。

CLIの参考推定額は実請求額ではない。定額契約やローカル実行も支払額0としない。料金版による評価がなければ未算定で、遅着・訂正の後は再評価待ちになる。料金・費用評価の作成と再評価は[既存APIの明示操作](usage-pricing.md)を使う。

## 同期とAPI

計測は暗号化した未送信queueから同じIDで再送する。Runnerの状態にある`last_observation.journal.pending_usage`は未送信計測の有無を示す。計測の同期失敗をRunの成功・失敗へ変換しない。Runnerを再起動しても、計測再送のためにCLIを再実行しない。

- `POST /runs/workspaces/{workspace}/executions/{id}/usage`: 割当端末からの計測報告。共通mutation、割当`generation`、UsageRecordの`value`と任意の`observed_at_ms`を送る。保存前とtransaction内で現在権限を確認する。
- `POST /usage/workspaces/{workspace}/query`: `mode=run`、`attribution_id`にRun ID、`kind`に表示種別を指定する。受信したcursorは同じ照会条件の次ページに使う。

既存UsageRecordの読取り・集計・料金APIは維持する。端末の資格情報や全文対話を計測記録へ添付しない。

## 検証

`pnpm run test:runs`が終了後報告・現在認可・再送・Run別ページを確認する。`pnpm run test:usage`は従来の重複排除と料金を確認する。`pnpm run test:desktop`は構造化イベントの変換・暗号化保留・再送・端末内モデル取得を確認する。実CLI試験は所有fixtureと採用版・既存認証を明示したignored testを使い、CIで利用者の資格情報を要求しない。
