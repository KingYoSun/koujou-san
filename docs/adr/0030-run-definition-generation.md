# ADR 0030: 自由入力からのRun定義と共通の検証・採用

状態: Accepted。Issue #30。初期の反映方式と作業場所は2026-10-18に本人が承認した。

## 判断

クライアントの共通Hostへ `definition` 目的を追加する。自由入力、原応答、質問と回答、要求送信の意図、操作IDによるusage、本人の引継ぎ、再送照合は既存clientopsを使う。別のモデル搬送や履歴基盤は作らない。

提案は `definition_utf8 / reason / questions / unknown` を持つ。共通の `run-definition-v1` の変更する項目だけをJSON文字列で返し、省略項目は維持する。未設定事項は操作の質問に残し、Run.pauseへ変換しない。検証できた案は初期値で自動反映する。項目別採用、破棄、手動編集も同じ定義の保存・静的検証・採用を使う。

生成前に対象の共有版と手動固定項目を保持する。未送信の固定値は操作方針へ保存し、モデルへは値を送らない。固定値の変更、元版競合、能力不足、未完了の応答は自動採用しない。生成中に画面の下書きを編集した場合は、その下書きへ結果を上書きしない。

作業場所は登録接続の設定とRun専用worktreeを使う。定義には端末と接続の論理IDを保存し、絶対パスや秘密値を生成しない。リポジトリ・commitは通常のRun割当で指定する。生成に使った能力と現在の接続能力を照合する。

## 読取りと実行の境界

HostにはContextの検索・関係探索・固定版取得・プレビューと、許可した定義のmetadata・固定能力の読取りだけを公開する。定義のmetadataは既存のContext本文・prompt・parametersを含めない。`none` はContextのtoolを公開せず、サーバー側でも取得を拒否する。現在の閲覧権限、送信禁止分類、Scope、必須と除外は共通契約で検証する。膨大なContextはページで絞り、全件列挙しない。

保存・検証・採用はRunを作らず、割当や開始も行わない。採用したCLI定義からの明示的な作成は、既存の入力解決とRun作成を使い、未割当のRunを一件だけ作る。CI観測と条件付き書込みは既存の工程制御へ渡す。実行依頼、リポジトリ指定、能力・権限の再確認は通常の割当・開始に残す。

既存の手動定義、Context選択、保存済み操作、Web/ネイティブの認証情報の保存方式とモデル上限は維持する。新しいDB schemaは追加しない。
