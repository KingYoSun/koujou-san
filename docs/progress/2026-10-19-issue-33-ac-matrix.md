# Issue #33: 設計書AC-01〜68の証跡対応

対象は[設計書§14.3](../../koujou-san-design-doc.md)の全68条件。本表は条件を変更せず、各機能の固定版・環境・実測を持つ既存記録と、[一巡の計画S1〜S7](2026-10-19-issue-33-plan.md)・[今回の証跡](2026-10-19-issue-33-evidence.md)を対応付ける。現在は受入の途中であり、表の未確認・待ちを初期リリースの完了へ読み替えない。

機能証拠はmainへ統合済みの#3〜32の記録を再利用する。各リンク先に対象commit、試験環境、成功/失敗・未実行、独立検品とCIを保持し、現在の統合状態は[current-state](current-state.md)で照合する。今回の変更はWindowsのGit起動オプション、LLMへ示す既存の引数/参照形式、受入の試験補助だけで、検索・探索・共有状態・料金計算の契約は変更していない。

一巡ではWindowsのrelease Runnerと実Ory、PostgreSQL、Bleve、ArcadeDB、Bifrostを使い、Codex/Claudeの別Run・別worktree、別メンバーの回答を記録する。同一Windowsホストの論理端末・別保存域と、別の物理PCは区別する。二モデル交換は#26/#30/#31の所有HTTPS二接続の試験を再利用し、今回の有料実接続はOpenAI API一接続。未確認のproviderや全モデルの同等品質は主張しない。

Manifest候補の実Gateway検証、採用したRigの直接接続、非経由CLIは#26と#24の記録で区別する。ユーザーが選んだRigへ方針を変更した事実を、Manifestの標準同梱とは扱わない。Hopper/Triageの実モデル利用量は取得した範囲だけを使い、料金未設定・欠測・非該当を実支払額0へ変換しない。
