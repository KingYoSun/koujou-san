## 完了範囲

有効な割当を受け取る独立Runnerをネイティブ側へ追加し、設定したローカルのprogram・引数・入力方式を使ってCLIを実行する。2026-10-17のユーザー判断により、画面を閉じても許可済みの割当・実行を継続する。停止要求と停止確認を分け、端末再起動後にCLIの継続を推測しない。

Runの固定input/Manifestを使い、原出力・終了状態と、明示した対話protocolのPause/配送/再開をAPIへ報告する。CLIの名前や疑問文から能力・Pause・合否を推測しない。資格情報・ホーム・CLI内部履歴・実pathを共有状態へコピーしない。

Context全件や過去Runの全出力を取り込まず、担当Runの索引付きページと固定参照だけを取得する。初期から大量のContextを管理する前提を維持する。CLIやモデルを使わない閲覧/編集/回答クライアントへ設定を要求しない。

完全な切断復旧・セッション再接続は#19、利用量は#20、検品分離は#21、Workflowと実行枠の制御は担当Issueへつなぐ。未確認の起動を自動で繰り返さず、本Issueのプロセス対応記録と共通Run状態を使う。

## 調査と試作の終了条件

現環境の読取りではCodex CLI `0.162.1`、Claude Code `2.1.300`、WSL `Ubuntu-22.04`を確認した。Codexはstdin・JSONL出力と明示resume、Claudeはprint・構造化入出力等の現行helpを確認した。確認済みなのは版と引数の存在であり、対話/停止/復元の成功とは扱わない。

独立Runnerとchildの試作で、親プロセス終了、監視の時間的中断/復帰、Runner再起動、CLI消失の四場面を比較する。利用者のPC自体をスリープ・再起動せず、所有する検証processで境界を再現する。実画面終了後の継続も最終のWindows受入で確認する。各場面の観測と継続の保証範囲をADRへ記録してから製品構成を確定する。

入力/対話/停止の形式は上記の固定スクリプトと採用CLI版で往復し、取得できない能力を未対応として明記した時点で接続調査を終える。未確認のCLI版や任意protocolの汎用化を本Issueへ追加しない。

予定対象はネイティブのRunner binary/ローカル設定/担当入力取得/child I/Oと報告、必要な端末API、共通Run表示、固定CLI fixture、ADR/runbook。#17のworktree準備、#16のPauseと原出力、共通認可と保存を再利用する。
