# Context編集・Scope整理・入力プレビュー

WebとWindowsアプリは同じContext画面と業務APIを使う。ログインしてWorkspaceを選ぶ。端末登録やハーネス設定は閲覧・編集の前提にしない。

## 文書を組み立てる

「Contextを新規作成」で文・段落・節・文書を選ぶ。本文やタイトルは端末の下書きとなり、保存操作で共有版を作る。検索結果の「参照候補にする」で子の固定版を選び、親の編集画面で追加・順序変更・削除する。共有する文を更新しても既存の親の版は変わらない。新版を親へ採用するときは、参照を選び直して親の新しい版を保存する。

「版履歴」では過去の本文を読む。「この版の内容を下書きへ採用」は、その内容を現在の共有版に対する下書きへ戻す。過去の保存データを書き換えない。

## Scopeで整理する

ScopeはProduct・Project・Milestone・Issueを独立して作れる。親は任意で、四階層やGitHubとの一対一対応を強制しない。Scopeの「直接所属を探す」で候補を表示し、開いているContextを別のScopeにも所属させられる。

「所属文書からの参照を確認」は、その文書の固定した子を辿る。子の直接所属は付与しない。所属変更は本文の版を変更しない。反映中の所属は「所属を再確認」で確認する。

## 入力を確認する

検索・関係探索・固定版の画面からinclude/excludeを選び、順序を調整する。「選択した固定版を確認してプレビュー」で選んだ版を再取得し、構造、抜粋、重複、除外、由来、固定添付、取得状態と実入力を確認する。空の選択と明示的な「注入なし」は区別する。

広い検索に続きがある状態と、選んだ固定版だけを確認する状態は別に表示する。エンジン停止、未反映、探索の打切り、権限不足、未取得参照は未完了とする。この操作ではManifestを保存せず、Run・CLI・CIを始めない。

## 下書きと移行

「下書き」には端末内の未送信データをページで表示する。切断中も下書きを保ち、再接続後は内容を確認して送る。競合の再適用と、結果不明の要求の再送を区別する。

旧版のWorkspace一括保存は初回に対象単位へ移行する。移行が失敗したときは元データを残して再試行し、未移行の上から新しい内容を書き込まない。移行後は旧版アプリを併用しない。サインアウトや権限失効を確認した対象の本文・下書きは削除する。

## 開発時の確認

`pnpm run test:mcp:ui`は、分離したOry・PostgreSQL・Bleve・ArcadeDBと二Userの画面を起動する。表示されたloopback URLは合成データ用で、標準環境のログイン情報を使わない。準備完了後30分で検証を打ち切り、`POST /__fixture/finish`で早く終了できる。HTTP中継は正規のOAuth tokenを更新する。認証やTLSを無効化する製品経路は追加しない。

専用の`/__fixture/`操作は通信・投影の停止/復旧と試験Userの権限変更に限るテスト内の入口で、製品サーバーには登録しない。秘密値を表示せず、終了後は専用Compose環境を削除する。Windowsの通常起動や画面操作は[Computer Useの手順](computer-use.md)を参照する。
