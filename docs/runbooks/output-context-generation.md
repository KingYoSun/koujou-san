# 出力からContextを作成・更新する

「作業と判断」のRun記録で原出力を開き、「この固定出力からContextを作成・更新」を選ぶ。Context画面の同名欄でもRunと出力の固定版を指定できる。

対象箇所はJSON pointerで指定する。空欄ならその出力全体を使う。「固定した出力と対象箇所を確認」で本文とdigestを確認する。元Runの入力や別チャンネルは自動でモデルへ渡さない。

生成目的とモデル接続を選ぶ。既存Contextは検索・Scope・関係探索で絞り、全Workspaceの本文やIDを先に読み込まない。「既存Contextを参照しない」場合は固定出力だけを使う。接続キーの保存、本人の引継ぎ、質問と上限は[Context選択](client-context-selection.md)と共通。

初期値では、現在の権限・元版・固定項目・由来を検証した変更を自動反映する。「案を確認して採用」へ切り替えたり、「手動でContextを編集」からモデルを呼ばずに案を作ることもできる。変更案では採用する項目を選べる。必要な子参照が欠ける構成や競合は一括反映せず保留する。手動修正は別の履歴へ保存してから採用する。

Sentenceの内容とParagraph・Section・Documentの順序付き参照、Scope所属を別々に扱う。所属先は生成前に取得する。既存Contextの本文・名称を守るときは、通常のContext一覧で選んでから「選択中Contextの本文・名称を固定」を使う。

結果一覧は50件ずつ取得し、各項目から通常のContext編集へ進める。由来欄には元Run・固定出力・箇所・生成操作・参照版を残し、観測、推測、判断、未確認提案を区別する。生成後の手動変更も表示する。自己申告は独立検品のPASSにしない。重複候補だけでは統合・削除しない。

新しい版は既存の全文書、過去判定、開始済みRunの入力へ伝播しない。別案件でも通常の検索・選択で再利用し、後段の工程へ渡す場合は、その基準版への明示採用とContext選択を行う。原出力を直接渡す接続とは由来を分ける。

## 新しい確定出力から自動生成する

「出力からの自動生成方針・担当・履歴」で目的・対象チャンネル・対象Run等・Scope・上限を保存する。保存だけでは有効にならない。「このクライアントを担当にして有効化」で、本人のモデル接続を使う担当を指定する。

有効化後に新しく終了したRunの指定チャンネルを、一件ずつ処理する。Context更新だけでは生成を始めない。同じ方針版と出力版の組は重複生成しない。過去分は別欄で期間を指定し、明示的に照合を依頼する。

担当画面を閉じると新しいモデル要求は止まる。送信済みで結果不明の要求は履歴に残り、勝手に再送しない。モデル障害や上限到達は保留・失敗として扱い、操作を開いて本人の引継ぎや手動修正へ進む。無効化後は新しいモデル要求と自動採用を止める。原応答と処理履歴は保持する。

## 検証

`pnpm run test:clientops` は固定出力、四粒度、競合、再送、クライアント終了、障害、上限と手動復旧を試験する。`pnpm run test:mcp` は実OryとSDKによる送信範囲を確認する。共通画面は `KOUJOU_TEST_OUTPUT_CONTEXT_UI=1` を設定して `pnpm run test:clientops:ui` を使う。所有モデルHTTPによる合成入力だけの試験で、実モデルや実キーは不要。
