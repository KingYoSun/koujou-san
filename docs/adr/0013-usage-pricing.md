# 0013: 利用量の計測範囲と固定版の費用評価

- 状態: Accepted
- 日付: 2026-10-16
- 根拠: 設計書§7.10・9.8・12.5、Issue #14、個別契約単価の採用と履歴の無期限保持に関するユーザー判断

## 判断

接続先・契約・実モデルを料金表の識別情報に含める。中央で全てのクライアント接続を登録・管理できる前提を置かず、個別契約単価も手動設定できる。既定ではWorkspace内で共有し、既存の役割・資源別権限を適用する。記録と料金・評価の版を無期限に保持する。

数量と金額は十進数の文字列で受け渡す。Goの`math/big.Rat`で計算し、料金版に記録した小数桁数と丸め規則を適用する。PostgreSQLのNUMERICで集計し、JavaScriptの浮動小数点数へ変換しない。要求モデルを実モデルへ転記せず、単価や数量が不明なものは未算定として残す。

原記録は取得元・変換版・イベント・系列・連番・増分/累積・外部要求・計測範囲を持つ。増分は取得元とイベントから、累積は取得元と系列から安定したIDを作る。訂正は共通の期待版と操作IDで新しい版として保存する。累積の最新値を過去の累積値へ加算しない。

相関できる計測範囲ごとに現在の系列を取得する。同一要求の取得元を名前順に比較し、一致する数量を一度採用する。欠測は取得できた項目で補い、値・単位・内訳・帰属などが矛盾するものは確認対象とする。明示的に子要求を含む親総量があれば子を再加算しない。採用元の固定版と、抑制した子を含む原記録への参照を残す。確認対象を課金済みの合計へ加えない。

総量に含む内訳を明示し、課金時には重ならない数量へ分ける。内訳専用の単価がない場合は、その内訳を含む総量の単価を使う。異なる数量単位を合算しない。

費用評価は固定版の原記録・料金・適用期間・情報源を参照する。報告額・単価からの推定額・API料金換算額・配賦額を別の評価として保存し、横断して合計しない。通貨は分け、明示的な換算では換算前の金額・レート・通貨・時点・情報源を残す。料金変更は既存評価を更新せず、再評価は前評価への参照を持つ別記録になる。利用量が訂正されたら、過去の評価を残して現在の集計では再評価待ちとする。

費用集計上のScope所属は利用量の帰属情報に保存し、Contextの所属を流用しない。複数Scopeのフィルターは和集合で選択し、一つの計測範囲を重複計上しない。案件・Scope・原記録・料金の参照先を現在の権限で確認してから、サーバー側で集計・ページ取得・exportを行う。MCPの固定版・none/exclude・分類規則も共通の認可を使う。

共通StoreのCAS・receipt・変更記録を使用し、HTTP・共通UI・MCPは同じ業務サービスへ接続する。MCPの料金変更には通常認証から明示した`price-edit`目的を必要とし、既存のContext編集権限へ暗黙に追加しない。参照は評価やRunを作らない。

## 選定理由と検証範囲

浮動小数点数と現在単価だけによる再計算では、正確な金額と過去の根拠を保てない。取得元ごとの総量の単純加算では、累積・CLIとゲートウェイ・親子で二重計上する。共通の原記録と固定版の評価を用い、集計する前に計測範囲を確定する構成を採用した。

Contextを巡回せず、索引付きの計測範囲だけを更新する。期間集計はPostgreSQLで行い、クライアントへ全件取得を要求しない。ページは反映位置・照会条件・利用者・MCP操作に結び付ける。1万件×3版・100Scopeでページ継続と索引利用を検証する。新しい性能SLAは設けない。

実CLIからの収集は#24、本格的な費用比較画面は#32で接続する。自動料金取得・請求書照合・自動配賦は含めない。
