# 導線監査13項目の修正

## 目的と範囲

依頼は[導線監査](2026-11-03-navigation-audit.md)のN01〜N13をすべて修正することである。基準commitは`7ac07c5ca529f101a33863b6cd9a507e393cc404`。開始時の変更は未追跡の監査文書だけ。確認区分はCとする。認可、接続資格情報、永続化、外部書込み、ネイティブ接続先の変更を含むため、固定成果物の独立検品を行う。

利用者はWorkspaceの管理者・編集者・閲覧者であり、空のWorkspaceからProjectと相談を作り、対象を設定し、失敗した操作を明示的に再開する。共有接続と権限の変更は管理者が判断する。一覧・検索・作成入口は対象一覧側、選択対象の編集・復旧は詳細側へ置く。画面遷移は対象と版を保持する。

説明段落、入力hint、副ラベル、用途のない状態表示は追加しない。必須入力のラベル、操作名、結果・エラー・権限不足は残す。変更は各指摘の操作と必要なAPIに限定し、Scope所属を権限付与へ変えず、WebへCLI実行能力を与えない。

## 未決事項と調査の終了条件

Giteaの新規作成資格情報はWorkspace管理者が共有接続として設定し、そのWorkspaceで作成を許可する方式を本人が選択した。リポジトリ名・所有者・公開範囲は作成時に指定する。既存tokenの用途は観測・起票であり、新規作成の許可として流用しない。N02/03/06/07はこの保存・認可境界で実装する。

Desktop API切替は現在のauth・Runner・cacheの所有境界を確認し、進行中の実行を停止せず切替できる範囲を確定する。進行中実行の破棄等が必要なら、その変更を実装する前に判断を確認する。ACLは既存の資源単位判定と管理者権限を公開管理操作へ接続し、Scope配下への自動権限伝播を導入しない。

## 検証と独立検品

各条件に関係するGo/Rust/TypeScriptの試験、UIの静的描画、client型検査、整形を実行する。必要なDB試験は既存の固定環境を使い、実アカウントのLLM消費や利用者のrepo新規作成はしない。ユーザーに手動チェックを依頼しない。以前拒否されたブラウザoriginを別経路で観測しない。1440px/1024pxの実表示を確認できない場合は未測定として記録する。

独立検品には基準と対象commit、上記条件、必要な仕様と試験結果を固定して渡す。実装者の履歴を継承しない別コンテキストで認可・保存・送信経路を確認する。受入条件の未達と回帰を解消し、CI成功後にmergeする。
