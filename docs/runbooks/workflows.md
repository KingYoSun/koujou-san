# 工程の定義・検証・実行

共通画面の「工程定義・検証・採用と実行」を使う。定義の保存・検証・採用では実行しない。Webからも実行依頼はできるが、ローカルCLIの起動は許可されたネイティブRunnerが担当する。

## 定義を編集する

Run定義はcommand、Contextの固定選択、派生契約、必要な能力と担当端末を持つ。Contextは明示した選択だけを解決し、全Workspaceを列挙しない。`none`には出力をContextとして接続できない。新RunのContextは`selection`から確定する。別のRunに属する既存Manifestをそのまま使わない。

工程定義はノード、依存する結果、合流、入力接続、人の選択肢、戻り先、予算を持つ。Run定義のIDと版を固定する。入力接続は前段のoutputのチャンネル・番号・キー、または派生結果のキーを選ぶ。`path`はキーや配列位置の文字列の配列で、式を実行しない。未選択の出力や会話は渡さない。

並列数は明示する。戻り先がある場合は有限のRun数を指定する。任意の時間・費用予算は追加開始を止める条件であり、開始済みCLIの消費上限は保証しない。費用は`reported`・`estimated`・`api_equivalent`・`allocated`の一つと通貨を選び、欠測や別通貨を0として扱わない。

項目とJSON原文は同じ定義を編集する。端末内の未送信下書きと共有版を区別し、自動送信しない。ファイルは新しい下書きとして読み込む。既存IDの更新は前提版を照合する。大きな整数を含むJSONは`value_utf8`で保存でき、開始入力は`inputs_utf8`を使える。

静的検証の結果を保存してから固定版を採用する。保存しただけの変更で採用版は動かない。定義、検証、能力の参照はMCPでも同じserviceと現在の認可を使う。取得・検証でcommandや外部起票を始めない。

## 自由入力からRun定義を作る

新しいRun定義の下書きで、生成に使うモデル接続を設定する。端末一覧は50件ずつ取得でき、確認済みの接続を選べる。作業目的と完了条件を自由入力し、「Run定義の生成を依頼」を使う。作業場所は接続設定とRun専用worktreeを使う。不足する情報は画面の質問へ回答する。

初期値は検証済みの定義の自動反映。毎回の承認は求めない。案を確認する方式も選べる。原依頼、原応答、生成した項目と元の値を比較し、採用する項目を選ぶ。案を下書きへ戻して手動修正することもできる。手動編集した項目は固定でき、モデルへ値を送らず保持する。競合時は現在版を確認して再生成または手動編集する。

Contextの取得は許可範囲の検索またはnoneを選ぶ。送信禁止分類・Scope・必須/除外は引き続き適用する。モデルへ渡す定義テンプレートはmetadataだけであり、本文や既存のprompt・parametersは含まない。

採用後も実行は始まらない。「未割当のRunを作成」で宣言した入力を渡し、そのRunを「作業と判断」の通常のRun画面で割当・開始する。リポジトリ・commitもそこで指定する。作成応答を確認できない場合は同じ要求を再確認し、別Runを重ねて作らない。CI観測・条件付き書込みの定義は工程に組み込む。

## 工程を進める

採用版から新しい工程実行を明示的に依頼する。必要な開始入力、リポジトリと固定commitを指定する。CLIの利用許可と能力を確認して割り当て、リポジトリを使うRunは既存の専用worktree・branch作成を使う。

工程の人の判断待ちは、その工程を編集できるメンバーが回答する。Run途中のPauseとは別の操作である。回答によって実行権限は増えず、後続前にも元の依頼者の現在の許可を確認する。Runnerの準備待ちはCLIのPauseとして表示しない。能力が変われば同じ未開始Runで再照合する。

新しい採用版を進行中の工程へ適用する場合は、未開始ノードと失効する判断を先に確認する。開始済みRunの入力と過去の判定は保持する。基準や対象が変わった判定は、工程上では`STALE`となる。変更前の入力から遅れて届いたPASSも新しい対象の合格に数えない。`retry`に`STALE`の戻り先を定義した場合だけ、その遷移で新Runを作る。無条件に全工程を再実行しない。

CI観測は登録済みのGitHub Appから既存CIを取得し、commit・実行ID・必須ジョブを照合する。観測commandの終了と外部CIのPASS/FAIL/INCONCLUSIVEを分け、CIを起動し直さない。

外部操作の定義には`write`で対象、固定commit、必須ノードと許容結果、条件付き操作の能力を指定する。`parameter`が示す実際のcommand引数も固定commitと一致させる。割当時と起動直前に現在の権限・対象・必須判定を確認し、接続先の保護規則を維持する。

## 記録を持ち出す

定義は固定版のJSON、工程実行は固定した位置のNDJSONとして保存できる。工程の採用変更・判断・各試行とRun記録を対応付ける。未観測・未取得を成功へ変えず、権限失効や取得失敗で記録が欠けた場合は完了印を出さない。TauriはDownloadsへ保存し、最後の固定版の完了印を確認する。

局所検証は`pnpm run test:workflows`、共通認可は`pnpm run test:mcp`を使う。画面・OSの確認は[Computer Useの手順](computer-use.md)に従い、既存の証拠で足りる実機操作を繰り返さない。
