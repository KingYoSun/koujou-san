# 作成拒否のリポジトリ記録を削除する

## 目的と範囲

基準commitは`ff31e778`。ユーザーは、作成に成功したrepoと並んで残る「作成拒否」の意図を確認し、不要な記録をkoujou-sanの画面から消せるよう求めた。送信の記録は再送防止と結果追跡に必要だが、拒否済みの要求を通常一覧へ出し続ける必要はない。

Workspace管理者が拒否済みの記録を選び、その記録を削除する。現在の一覧からは消し、共有履歴と操作のreceipt、削除済みの版を残す。Giteaへ削除や作成を送らず、同名の作成済み接続を維持する。結果不明や送信途中、登録済み・作成済みの接続の削除、全履歴の消去、復元画面は対象外。

UIの判断は次の三点に固定する。利用者はWorkspace管理者で、選んだ拒否記録を片付けるか判断する。中央の一覧が現在の接続・要求、選択後の既存フォームが対象の詳細を示す。変更は拒否記録の詳細へ「作成拒否の記録を削除」を追加し、操作後にその記録と選択フォームを消すことだけとする。成功済みや結果未確認の表示・操作は維持する。

## 受入条件

| 条件 | 対象と期待結果 | 判定方法 |
| --- | --- | --- |
| AC-D1 | 管理者が選んだ拒否記録を削除でき、再取得後も一覧から消える。同名の成功済み接続は残る | 専用DBのAPI試験、所有HTTPと実フォーム、実環境の通常UIで対象を選択して確認 |
| AC-D2 | 非管理者・別Workspace・現在の対象更新権限がない要求、古い版、拒否以外の状態の削除を拒む。同じ削除要求の再送は同じ結果を返す | APIの権限・状態・版・receipt試験とコード照合 |
| AC-D3 | 拒否記録の詳細にだけ削除操作を表示し、成功・失敗を既存の通知へ示す | 静的描画と実フォームの試験、1440px・1024pxで実表示・横スクロール・focusを確認 |
| INVAR-D1 | Giteaへ削除・追加送信を行わず、成功済みrepo・共有接続・未確認要求を変えない | 所有HTTPの要求数、保持する記録、実環境のGitea表示を照合 |
| INVAR-D2 | 削除を共有状態へ記録し、過去の送信意図の再送を防ぐ。schemaと50件のページ取得を維持し、全件取得や全履歴走査を増やさない | tombstone・共有履歴・古い作成要求の再送試験、SQLとAPI差分を照合 |

## 実装と検証

保存・認可に関わる区分Cとして、固定commitの独立検品を行う。既存の`mutate`から削除フラグを保存できるようにし、拒否状態の行だけを削除する。Workspace管理権限と対象の更新権限を共有状態のlock内で確認し、現在版とreceiptは既存処理へ任せる。行の削除と共有の削除版を同じtransactionで保存する。

`test:forge`の既存専用DB・所有HTTPと実フォームを拡張し、削除前後、保持対象、権限、版、再送とGiteaへの要求数を確認する。共通UIの型検査・対象テスト、`check`、必須CIを実行する。配備・実操作の結果と最終判定は、この記録を参照するPRの結果欄へ集約する。個人環境の値や画像はGit管理外に置く。
