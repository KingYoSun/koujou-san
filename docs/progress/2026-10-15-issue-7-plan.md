# Issue #7: 四段階Context・Scope所属・入力版の確定

- 対象: Issue #7、Scope revision 1、区分C。
- 基準: #6をマージした`491ecd9c6a6640f0f0d857a21069c848019eaf23`。
- 現在の判定はcurrent-state.mdへ集約する。

## 目的と範囲

Sentence、Paragraph、Section、Documentを不変の版で保存し、Scopeへの所属履歴と入力選択を別に管理する。明示参照を実DBで解決し、入力の構造・順序・原内容・由来をContextManifestへ固定する。共通業務APIとGo/TSの共有fixtureまでを扱う。

LLM選択・生成、Runner配送・CLI起動、Bleve/ArcadeDBの候補取得本体は対象外。Context編集GUIは#12で扱う。後続機能が使う基準版・output・pause・探索完全性は、本Issueの業務型と固定fixtureを接続境界にする。

## 固定する条件と確認

Issue本文のAC-1〜8・INVAR-1〜5を維持する。以下の末端fixtureで合否を判定し、新しい利用場面を追加して完了を先送りしない。

| 条件 | 対象と期待結果 | 判定方法 |
| --- | --- | --- |
| AC-1 | 四粒度の単独保存・型付き参照・共有子・順序。型違い、参照切れ、循環を拒否 | 実PG登録と解決をそれぞれ成功/拒否で照合し、原内容をGo/TSで再構成 |
| AC-2 | 四種類のScopeへの複数所属。文書構造・内容版・所属を独立 | 同じContextの複数Scope所属と履歴を比較し、親の所属変更で子が変わらないことを確認 |
| AC-3 | 子の更新で親の既存版を変更せず、明示採用時だけ新しい親版 | 更新前後の本文・参照・順序と過去版を実DBで比較 |
| AC-4 | none、未指定、select。Scopeの既定値を暗黙継承せず、noneと直接値の併存を拒否 | 同じ候補で3設定・併存を比較し、無注入のManifestを保存 |
| AC-5 | include順、親子直接選択の重複整理、共有配置の保持、全経路へのexclude、異版衝突 | 見出し・段落・抜粋・空コンテナを含む固定入力とManifestを比較し、最新版へ自動置換しない |
| AC-6 | Workflowの内容版・所属基準を固定し、明示採用は未開始Runの新基準へ適用 | 共有更新前後の旧基準、明示採用の影響と新基準、開始済み入力とdigestの不変性を比較 |
| AC-7 | 未取得外部参照、権限不足、容量超過、探索未完了を別の不足状態として返す | 4失敗を注入し、完全なManifest・開始可能を返さない。必須情報の省略や古いコピーへの置換なし |

## 実装と検証の順序

1. 下記の判断を得た後、四粒度・所属・選択・Manifestの正式schemaと失敗理由をADRへ記録し、概念例をGo/TS共有fixtureへ写す。
2. 追加migrationと`internal/context/`で内容版、参照、所属履歴、基準、Manifestと追加情報を保存する。#4の原子的な更新・再送・版照合を使い、#6の認可を各対象で確認する。適用済みmigrationを変更しない。
3. 明示選択の型検証、重複・除外、構造を保った組立、digestと不足範囲を共通解決処理へまとめる。外部参照は固定版・範囲・digestと取得状態を記録し、未取得を本文として扱わない。
4. HTTPの認証済みUserから同じ業務処理を呼ぶ。Workflow/Runの実行を先取りせず、基準の採用と開始時入力の固定・追加情報を独立した記録境界にする。
5. 関連Go/TS fixture、分離PG、既存保存・認可の影響、`check / test / build`を確認する。固定commitの区分C独立検品、CI、マージ後照合を終える。

## 採用した判断と調査の終了条件

2026-10-15にユーザーが次の2点を採用した。

- 新規ContextはWorkspace参加者へ共有し、役割に従って閲覧・編集する。包含・参照・Scope所属から権限は付与しない。

正式schemaは設計書§8の概念例を再構成し、AC-1〜8の有限fixtureがGo/TSで一致した時点で確定する。探索の反映位置・部分結果は#9/#10へ渡す状態を定め、両エンジンの実接続済みとは扱わない。Contextの包含・Scope所属からアクセス権を付与しない。
