# Issue #27: サーバーLLMによるHopperの意味判断

- 状態: In progress。Scope revision 1、区分C。
- 基準main: `4638bbd61510a365a03bb134d2a2415ec521fc45`。#26は全CI・独立検品・マージ後tree一致を確認してClose済み。
- 目的: クライアント不在でも、成功Runに残された見送り問題を固定証拠から評価し、保存済み判定を通常のHopper発行へ接続する。
- 対象外: #28のTriage優先度、クライアントRigの変更、Run実行器の変更、Gatewayへの業務認可・発行の委譲。

## 確定した判断

2026-10-18の本人回答により、Bifrost OSSを標準構成の任意サービスとして同梱する。初期の検証版はHTTP 2.3.0、source `9237ec06672406e437b3cb33fc793ffd0403b3ae`、image `sha256:8f37e33a8caa85faf59a875605c61d1d934738e517d8fe96e2d9fcf6f0ef9098`。専用保存・管理認証・更新復旧を整備し、外部の互換接続にも交換できるようにする。クライアントやCLIの資格情報をコピーしない。

変更可能な初期値は、評価入力1 MiB、出力4096 token、一要求120秒、Worker最大2試行、Workspace同時2評価。容量超過時は省略して推論せず保留する。Gatewayの自動retryは無効とし、fallbackは明示した許可範囲だけにする。欠測費用を0にしない。

遅れて同期した必要な証拠と元結果の訂正は、関係する評価だけ自動再評価する。過去判定と既発行の関連、追加の推論消費を残す。定義・評価Contextの更新だけで過去全件を再評価せず、対象条件を指定した一括再評価を別操作にする。Context全体の列挙や本文取得を通常経路へ置かない。

## 有限な判定条件

IssueのAC-1〜10とINVAR-1〜3を維持する。各条件の対象・結果・判定は次のとおり。

| 条件 | 対象・期待結果 | 判定方法 |
| --- | --- | --- |
| AC-1 | 成功Runの見送り問題をサーバーが固定証拠から評価し、元Runの成功を保って発行へ接続 | クライアント不在の専用Run・Worker・Gatewayと発行記録を照合 |
| AC-2 | 証拠不足・未同期・形式不正・時間切れ・障害を不成立へ変換しない | 入力待ち・判断不能・失敗のfixtureと原応答を照合 |
| AC-3 | 応答前後のWorker停止でも採用判定と発行は一意、追加推論も記録 | 所有HTTPの停止位置とDB保存、再送・同時取得を比較 |
| AC-4 | 入力・定義・遅着訂正の再評価は別履歴、発行先への入力は分離 | 固定版と由来、既発行の関連、検品RunのManifestを比較 |
| AC-5 | 取得前と確定前に現在の自動化権限・送信分類・テンプレート・予算を検証 | 権限失効・禁止証拠・ログ内指示・費用欠測の拒否を確認 |
| AC-6 | 固定OSS Gatewayの構造化応答・モデル・相関・usage・許可fallback・保存・復旧と採用条件を記録 | [隔離probe](2026-10-18-issue-27-gateway-probe.md)と任意サービスの起動・復旧・依存確認 |
| AC-7 | 不成立・不明・失敗・再試行の消費を評価へ帰属し、Runや連鎖で重複集計しない | 共通usageの数量・料金版・所有者・連鎖集計を照合 |
| AC-8 | 保存・有効化・停止・提案/自動発行・発行しない過去評価を共通画面から操作 | 根拠・履歴・費用・上限・保留・待機先・明示再開の画面確認 |
| AC-9 | Gateway障害時も決定論Hopperと手動操作を維持 | 意味判断だけの保留/失敗と、既存の決定論・閲覧・編集を比較 |
| AC-10 | GUI/HTTP/MCPが同じ版・認可・serviceを使い、参照操作は実行を増やさない | 共通fixtureで再送収束、別Workspace・非公開証拠・秘密値の拒否を照合 |
| INVAR-1〜3 | サーバー/クライアントの設定・認証・帰属を分離し、保存後再送で再推論せず、CLIをGateway経由へ強制しない | 呼出主体、保存前後の上流要求数、Run用設定を比較 |

## 実装と調査の終了条件

既存HopperのStore/CAS/receipt、永続Worker、発行と連鎖、Context解決・認可、usageを再利用する。HTTP中はDB transactionを保持しない。送信前の予約と消費の仮記録、原応答の保存、現在条件の再検証、通常の発行を分ける。保存済み判定の再送ではモデルを呼ばない。

変更予定は`internal/hopper`、必要なサーバーHTTP接続・設定、access/usageの共通経路、HTTP/MCP、共通Hopper画面、追加migration、任意のComposeサービスと手順。旧migrationを変更せず、既存の決定論定義はそのまま読む。

候補の調査はAC-6の有限な表を埋め、構成・保存・管理認証・依存・復旧を記録して終了する。実provider試験が必要になった時点で、接続先・合成入力・消費上限を具体化して本人へ確認する。実契約や秘密値を無断で使わない。

実装後は関連PG/HTTP/MCP試験、共通画面の一巡、固定commitの独立検品、最終CI、マージ後tree一致、手動Closeまで確認する。#33へ移管済みの実スリープと人の初見操作は追加依頼しない。
