## プロセスと認証

ユーザー判断により、RunnerはWindowsの画面とは別プロセスで動作し、画面を閉じても許可済みの割当・実行を継続する。GUIはローカル設定と起動要求を渡す。Runnerは割当端末の資格情報でAPIへ接続し、GUIのOAuthセッションを共有状態へ渡したり、利用者を偽装したりしない。

所有するWindows processの試作で、親終了後の子の継続、監視の時間的中断後も同じCLI PIDであること、Runner消失後のCLI継続と新しい監視側が再発行せずUnknownにする境界を確認した。実OSのスリープ・再起動を行った結果とは区別する。Windows/WSLのstdin・stdout/stderr・終了コードも同じ95-byte入力で往復した。GUI終了後の製品Runner継続は、Windows画面から起動した同じRunner/CLIのPIDと、その後の二Pause配送・再開・正常終了を照合して確認した。[受入証跡](../progress/2026-10-17-issue-18-evidence.md)を参照する。

開始前に入力固定版・現在の割当・世代・端末利用方針と、端末内のprogram/引数/入力方式を照合する。起動前の記録を残してからchildを作り、起動できた事実を報告する。Runner再起動時に起動途中・実行中の記録を見つけても再発行しない。完全な切断復旧とセッション再接続は#19で接続する。

## 接続と入力

共有commandは論理的なkind/targetと要求を保持する。programの実path、引数template、環境変数への参照、作業場所は端末だけに保存する。端末の既存CLI認証を利用し、秘密値をRun.inputや共有定義へ複製しない。子へ渡す環境を組み立て、API/DB等の開発用秘密値を一括継承させない。

stdin・引数・ファイルは接続が宣言した方式で渡す。文字列の内容と構造化値を区別し、省略したcontext/promptを補完しない。ファイルや引数を使う接続は明示したtemplateへ値を渡す。未対応・曖昧な方式はprocess開始前に拒否し、固定inputを保持する。

Windows CLIとWSLの接続を対象にする。接続ごとに版・環境・確認状況を記録し、CLI名だけで対話・停止・復元を保証しない。Codex `0.162.1` とClaude Code `2.1.300` は同じ合成promptで実接続し、期待する原文と終了コード0を確認した。

## 原出力と対話

全CLI原ログを端末で保持する。通常のスクリプトのstdout/stderrは原文・チャンネル・順序・出力元をRunへ保存する。Codex/Claudeの構造化接続では、既知の作業出力イベントを原文のまま記録し、CLI初期化・ローカルpath・接続設定等の診断情報は端末の原ログ参照として扱う。本文を同期していない参照は未取得と表示し、取得済みの全量ログと偽らない。Contextを一件ずつ分類する操作は要求しない。

汎用の対話接続は明示的なJSONL protocolを使う。`koujou_event`に包んだPauseと継続確認だけを解釈し、自然文の疑問文からPauseを生成しない。開始inputと、Pause ID/response IDに対応する回答は別のframeで渡す。APIでの回答受領、childへの配送、childが返した継続確認を区別する。所有する外部スクリプトの試作で二回の往復を確認した。

停止は接続が対応する場合だけ試みる。要求受付をCancelledへ変換せず、実際のchild終了を確認してから報告する。既に行ったファイル作成等の外部副作用を取り消したとは扱わない。対応しないCLIには未対応を示す。
