# 0007: 同期・下書き・再送の境界

- 状態: Accepted
- 日付: 2026-10-15
- 対象: Issue #8、設計書§11、[計画](../progress/2026-10-15-issue-8-plan.md)

## 取得と現在の権限

同期はHTTPで更新位置を定期照合し、snapshotまたは差分を取得する。通知や更新位置の一致だけで本文を確定せず、欠落・重複・遅延があっても再取得で照合する。cursorはWorkspace・User・固定した取得範囲へ結び付け、毎回現在の権限を確認する。

Contextの不変記録に確定時のstream sequenceを対応付ける。snapshotはその位置以前の最新の版をページで返し、共有更新履歴が失われても本文の不変記録から再構成できる。既存データの対応は追加migrationで行い、適用済みSQLは変更しない。差分は#4の連続性検査を使い、欠落・不明な位置ではsnapshotを要求する。

一覧はページ単位で取得する。共通画面は最初のページを表示し、利用者が続きの取得を選べる。全グラフを自動で端末へ渡さない。差分は取得済みの対象を更新し、新しい未取得項目は取得の案内とする。snapshotの続きを取得した後も、基準位置以降を照合してから確定キャッシュへ反映する。

共有本文と、その本文を含むManifest等の現在の権限を照合する。クライアントが申告した取得済みIDについても現在の再利用可否を返し、確認した権限外の本文と下書きを削除する。通信断中は権限変更を確認できず、最後に確認できた時点のキャッシュと表示する。

## 端末側の保存と送信

API接続先・User・Workspaceで保存領域を分け、確定キャッシュ、未送信下書き、結果不明の要求を分離する。Webは同一originのIndexedDB、WindowsはDPAPIで保護したローカルファイルを使う。OAuth・Deviceの資格情報や端末パスを同期データへ混ぜない。

ユーザーの採用判断により、サインアウト・Workspace権限失効を確認したときは該当する本文キャッシュと未送信下書きを削除する。再接続しても下書きは自動送信せず、本人が内容と前提版を確認して送る。競合では最新内容と下書きを並べ、明示的な再適用を新しい操作として扱う。

送信前に操作ID・前提版・送信内容を保存する。応答喪失ではその要求を結果不明のまま保持し、本人の再送でも同じ操作IDと内容を使う。新規Run・割当変更・外部起票・pause回答をこの編集下書きの送信経路へ入れない。受付、同期で確認した状態、CLI等の実結果を分ける。

## 実行報告の接続境界

報告はDevice主体・許可Workspace・担当対象の認可後に受け付け、生成順序・重複・欠落を照合する。同期する値は論理参照と観測の種類に限定し、任意の端末パス・環境変数・資格情報を共有DTOへ入れない。報告の受付や順序の充足を、Runの成功やCLI再開の確認へ置き換えない。実Run状態機械・配送・プロセス照合は#16以降が接続する。
