# ADR 0032: 条件を保存する費用・品質・時間の二群比較

状態: Accepted。Issue #32。2026-10-19に本人が、条件で二群を保存しサーバー集計を並べる初期画面を承認した。

## 集計と比較条件

既存usageの計測範囲・版・認可・十進数・集計cursorを共用する。`compare / compare_details / compare_quality` を追加し、従来の一覧・集計・exportを維持する。Context・Manifest・Run/工程定義の固定参照は `basis` で絞る。参照した固定版をすべて含む計測だけが対象となり、分類やScope所属から閲覧権限を増やさない。

二群の条件は `comparison:` の版付き記録として既存usage保存へ置く。保存するのは名称、期間・Scope・モデル・固定参照等の条件で、全RunやContext本文を保存しない。Scopeと固定参照は現在の認可を依存条件へ残す。モデル接続の中央登録は要求しない。

比較の基礎は重複排除済みの利用記録。選んだ評価種別を左結合し、未評価または権限のない単価を使う金額は未算定にする。非公開の単価・案件・由来は返さない。複数Scopeに属しても消費を一度だけ数え、通貨・評価種別・実モデル・取得範囲・契約方式を分ける。計測範囲が未確定の数量を確定集計へ含めない。

## 品質・時間と手動改善

時間は固定したRun記録から取得し、要求数や通貨数で重複させない。実行時間は開始から終了で、Run内の回答待ちを含む。開始待ちは作成から開始までとし、欠測は欠測のまま表示する。手戻り・再実行は明示された前Run参照を数え、失敗から推測しない。

品質には保存時の判定を使い、独立検品とCLI自己申告、未確認を分ける。検品の固定条件版をページで示し、現在の有効性は通常の検品画面で確認する。異なる条件や計測範囲、異なる反映位置を隠して優劣や支払削減を断定しない。

根拠から既存のモデル接続・Context・定義編集へ移る。変更したContextや定義は通常の保存・検証・採用を使い、次のRunへ明示適用する。比較の読取り・保存や費用の上限だけでは設定・検品・Runの状態を変更しない。

料金保存は過去評価を変更しない。再評価では元計測、料金固定版、前評価を明示し、新しい評価を既存APIへ保存する。比較条件と表示ページは書き出せる。全利用記録をGUIへ取得して合計しない。

## 保存と互換性

migration 25はusage記録へ比較条件の種別を追加し、固定参照・計測範囲の検索索引を追加する。過去のmigrationや原記録、料金・評価の意味は変えない。比較条件は現在の権限で読み、本文や資格情報を含めない。DBの通常のbackup/restoreと標準配布の更新試験へ含める。
