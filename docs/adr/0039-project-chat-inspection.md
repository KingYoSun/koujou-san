# 0039: 相談開始の自動化とProjectの状態・ファイル参照

状態: 採用。2026-11-06の直接依頼と選択回答による。

## 判断

相談ごとの画面を維持し、ChatGPTを参考にした導線へ改める。最初の送信で既存のスレッド・メッセージ保存を使い、本文の冒頭から題名を付ける。ProjectとLLM接続の選択はAPI・利用者・Workspaceごとに端末へ保存し、現在の権限と接続を再確認して復元する。画面表示や復元ではモデルを呼ばない。会話本文・資格情報をこの選択記録に保存しない。

同日の追加回答に従い、同じ相談の直近20件から完了した発言を自動で選ぶ。入力欄の「履歴」に送信件数と対象を表示し、不要な発言を除外できる。保存済みの固定参照を古い順で今回の入力に添え、別相談や未完了の発言は含めない。以前の表示ページを開く操作で送信範囲を拡張しない。ADR 0033の毎回の手動選択をこの既定動作へ置き換える。

相談から開発準備の設定・実行状態・登録リポジトリ内のREADMEとコードを確認する。新しい相談操作の `chat.inspect` に参照の選択を保存する。従来の方針にこの値がなければ、既存のContext参照範囲を維持する。

`project_inspect` は相談の保存済みProjectを起点に、本人の実行権限・選択モデル、Projectのリポジトリ、WorkspaceのRunnerとRunの状態を返す。モデル指定のWorkspaceやProjectへ切り替えない。Runner・RunのページはWorkspace内の現在権限を確認し、その範囲であることを明記する。Runnerの接続時刻・有効期限と実際のCLI成功を区別する。

`repository_read` はProjectへ関連付けた登録リポジトリだけを読む。既存のGitea接続解決・認証・現在認可を使い、任意URLや端末pathを受け取らない。初回に既定branchをcommitへ解決し、以後はそのcommitを指定する。ファイル一覧は50件のページ、UTF-8本文はHTTP Rangeによる32KiBの範囲で取得し、続きの指定を返す。全件取得を前提にせず、登録先の内容と端末の未commit変更を区別する。参照先、commit、path、範囲を回答の根拠にする。

両toolはchat目的・明示した参照方針・現在の送信禁止分類を照合する。取得した固定参照は既存のread operationへ結び付け、共通のMCP監査へ記録する。モデルに返す情報へ資格情報を加えず、ファイル内容を操作権限にしない。ファイル編集・CLI実行・Run開始・外部書込みは追加しない。

## 互換性と確認

既存スレッド・メッセージ、Contextへの仕様採用、要求ID、送信意図・原応答・利用量と中断復帰を維持する。保存構造の移行は不要。返答はMarkdownとして表示し、生HTMLを実行しない。

ADR 0033の保存・採用・復帰契約は継続する。相談の手動作成、毎回のProject・接続選択、chatからContext以外を参照できなかった範囲を本判断で置き換える。
