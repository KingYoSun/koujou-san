# 三つの画面パターン

[入口](../../DESIGN.md) / [部品](components.md) / [見本](examples/ui-patterns.html)

以下の三つだけを今回の参照パターンとする。合成の値は視覚表現の説明用で、機能・優先度尺度・件数上限・新しい権限を定めない。実際の操作は各機能の既存契約に従う。

## 1. Context選択と注入プレビュー

検索条件とページ継続を上部、取得した候補と選択条件を左、確定する入力と版・由来を右に置く。狭い画面では同じ順で縦に並べる。少数の行をすべてのContextと呼ばず、「取得ページの抜粋」と明記する。

文書構造、Scope所属、Runへの注入は別の行で示す。所属や参照から注入・権限を暗黙に付けない。`include`／`exclude` はラベルと記号で示し、無注入は「注入0件」と明示する。無注入でも成果物・実行条件が消えるとは表現しない。

プレビューには固定版、由来、対象のRunまたは定義、入力の範囲を付ける。AIの提案と採用済みを分け、手動固定を示す。例では「条件付き注入／無注入」のタブで表示だけを切り替える。[Contextの操作手順](../runbooks/context-ui.md)と[LLM選択](../runbooks/client-context-selection.md)が業務上の正本になる。

## 2. Runの質問待ちと成果確認

目的、実行状態、待機理由、回答対象を先に示す。その後に固定成果物・証拠・版、回答欄を置く。実行状態と検品判定は別に置き、質問への回答だけでRun再開済み・検品合格と見せない。

見本は「質問待ち」「検品: 判断不能」「接続: 切断」「同期: 未同期」「後続: 未実行」を別に表示する。成果物への参照と回答理由を残す。見本の回答ボタンは外部へ送らず、ページ内で入力済みの見本通知だけを表示する。[Run](../runbooks/runs.md)と[作業と判断](../runbooks/work-and-decisions.md)の権限・再開条件を変更しない。

## 3. Issue優先度と費用

Issueの目的、推奨優先度、採用中の優先度、手動固定を同時に読めるようにする。推奨を自動的に採用値へ見せず、尺度名と評価の版を添える。見本の「高／中」は例示尺度であり、全Workspaceの段階名ではない。

費用は取得済み・推定・未取得を文字で分け、金額の桁を揃える。モデル名、単価の由来、計測範囲を補足に置く。未取得は「—／未取得」、推定は「推定 ¥…」とし、合計に紛れ込ませない。Hopperの発行判断、Triageの優先度評価、クライアントLLM操作、Runの数量を識別して表示する。[料金と集計](../runbooks/usage-pricing.md)、[自動化](../runbooks/automation.md)、[比較](../runbooks/run-usage.md)の契約を維持する。
