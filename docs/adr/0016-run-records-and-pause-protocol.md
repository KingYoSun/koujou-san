# 0016: Runの共通記録・Pause応答・固定版export

- 状態: Accepted
- 日付: 2026-10-16
- 関連: #16、設計書§6.4・7.1〜7.9・11.1・11.2、ADR 0002・0003・0005・0015。

## 判断

GoのRun業務serviceを共有正本とし、Runの小さな状態、固定入力、Pauseの版、原出力、構造化報告、確定結果、前後Runの関連をPostgreSQLへ保存する。同じ共有更新のtransactionで版・変更記録・receiptを確定する。出力追加ごとに入力全文や全履歴を再保存しない。Context総件数を列挙せず、選択済み固定入力と索引付きページを使う。

commandはkind・target・任意のparametersと、入力の受け渡しを示すbindingを持つ。context/promptは任意のJSON値であり、commandだけでも成立する。指定した入力に受け渡し方法が無ければ拒否し、入力を捨てない。実際の接続能力・Runner割当・CLI起動は#17以降で確認する。

Manifestを使うときは、その固定版のRun IDと現在認可を確認する。Run.input.contextは固定Manifestへの参照を保持し、本文をRunの各状態版へ複製しない。明示したinput取得で固定Manifest本文も読め、exportにはManifestの固定内容を含める。任意のJSON値の形から参照や実行権限を推測しない。

作成・開始依頼・起動確認は別操作とする。作成では起動しない。開始依頼は実行依頼の許可を確認し、execution_requested_atを保存する。実際の起動時刻は、現在の担当端末からstartedを受理して初めて記録する。未実装の割当を、準備完了や起動成功として扱わない。

Pauseの未解決要求は同じRunで一つとし、解決済みも版付きで残す。ユーザー判断に従い、そのRunを編集できるメンバーが回答でき、実行依頼の許可は要求しない。回答受領、担当への配送確認、同じRunの再開確認を別状態にする。応答ID・Pause ID・順序・CAS・receiptで再送と競合を処理し、古い質問への回答や二重再開を拒否する。人の回答を待つuserと外部イベントを待つeventを区別する。eventは担当接続の観測報告で応答を受け、観測元・担当端末を由来に残し、人の回答へ偽装しない。

報告は現在許可された担当端末の資格情報で受け取り、構造化イベントと連続した順序を確認する。未確定のsync-reportは昇格しない。原出力の値・チャンネル・順序・出力元はそのまま保存する。接続断は観測Unknown、取消要求は要求だけであり、最後の実行状態や取消確認とは分ける。終了コード0と派生のPASS/FAIL/INCONCLUSIVEも別データとする。派生名は固定列挙にせず、JSON Schemaと任意の判定欄を宣言できる。外部schema取得は行わない。

終了後の再実行、目的・command変更、検品後修正は新しいRunを作り、固定版の関連元を指定する。元Runの終端/input/outputは書き換えない。関連先も独立した現在認可を受け、関連だけで権限を得ない。

HTTP/GUIは同じ業務serviceを使う。MCPは要求された参照・ページ取得を公開し、更新や実行へ変換しない。現在の参加・資源権限と操作範囲、none/exclude、依存資料の許可を確認する。出力や指示文はデータであり、後続の権限にはしない。

exportはrun-export-v1のNDJSONとする。選んだRun固定版までの記録、固定Manifest、開始時に固定した関連ページの範囲を保持する。大きな記録はページとストリームで転送し、途中失敗をcompleteにしない。Webは直接ダウンロード、Windowsは認証付きストリームをDownloadsへ保存する。全量をIPCへ載せず、固定版と完了フレームを確認してから部分ファイルを正式名へ変える。書出しは元commandや外部サービスを更新しない。

## 理由と比較

全Runを一つのJSONへ追記する案は、部分出力ごとに入力・履歴を複製し、増える出力の取得も全件になるため採用しない。別のStage/Attemptエンジンも追加しない。既存の共有保存・現在認可・Contextの固定参照・schema検証を使い、責務をRun記録へ閉じる。実行担当の獲得や実CLI操作を今回のserviceへ仮実装しない。
