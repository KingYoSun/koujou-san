# 0012: GitHub Appによるサーバー側の観測

- 状態: Accepted
- 日付: 2026-10-16
- 対象: Issue #13、設計書§6.3・6.5・11.3・11.7、ユーザーの認証・照合・保持方針への回答

## 判断

GitHub Appのinstallation tokenで、登録したIssue・PR・commit・Actionsをサーバーから観測する。Appの秘密鍵はサーバーの設定ファイルから参照し、共有状態・ブラウザ・クライアントの同期へ渡さない。tokenはinstallationとrepositoryごとに、Metadata・Issues・Pull requests・Contents・Actionsのreadだけを要求して発行する。GitHubへの業務要求はGETだけとし、token発行のPOSTを業務上の書込みと区別する。

初期の定期照合は60秒を目標とし、サーバー設定で変更できる。APIの残量・Retry-Afterに従って減速し、遅延を表示する。公開入口を持つ配置ではHMAC検証付きWebhookも利用できる。通知は登録対象を再取得待ちにするだけで、payloadを現在状態として保存しない。Webhookを導入条件にしない。

同じ外部対象への参照は一つのtargetへまとめ、Workspaceとの対応を別に保存する。対象の一覧・履歴は索引からページ取得する。Contextの本文や全件の走査から外部対象を探さない。変更があった観測履歴は期限なしで保持し、同じ内容の再確認では履歴を増やさず最終確認時刻を更新する。CIログ・成果物の全量コピーは含めない。

## 観測の意味

Actionsではrepository・head SHA・workflow ID・run ID・run_attempt・ジョブを対応付ける。各回のジョブをページで取得し、取得途中で実行状態が変化した場合やページが欠けた場合は完全な観測として確定しない。必要ジョブと指定commitの照合は、GitHubのCI conclusionと別に表示する。工程の受入判定やWorkflowの前進をこのConnectorから確定しない。

接続断・認証拒否・取得中断では、最後に成功した結果と取得時刻を残し、現在の観測をUnknownまたは未取得とする。GitHubを実状態の正本とし、共有観測を取得時点の記録として扱う。

## 比較した方式と配置

GitHub Appは個人と組織の双方へ導入でき、共有運用で発行者個人の継続在籍に依存しない。fine-grained PATは個人の導入が軽い一方、発行者の権限・期限に依存する。ユーザーは初期方式にGitHub Appを選んだ。PAT・OAuth Appを並行した初期経路として残さない。

サーバーが動作中ならクライアント終了後も照合を続け、サーバー再起動時に登録対象を再照合する。サーバーも停止している間は照合できず、最後に保存した観測を現在の結果として補完しない。ローカル利用では同じAPIサーバーを端末内で動かせる。共有利用ではサーバー運用者がApp設定とWorkspaceへの公開範囲を管理する。導入のために既存repoやCIファイルを移動・書換えしない。
