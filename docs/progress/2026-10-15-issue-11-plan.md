# Issue #11: MCP参照・検索APIと共通認可

- 対象: Issue #11、Scope revision 1、区分C。
- 基準: `1f9acedb7cd091ef9da10c5bb8c4fd665b991305`（#10完了後のmain）。
- 状態: In progress（大規模Contextと送信禁止分類を前提に設計を見直し中）。初期の接続元はkoujou-san自身のクライアントとし、セットアップ時の事前登録で進める。製品実装は未着手。

## 目的と範囲

認証済みStreamable HTTPのMCPから、既存のContext検索・探索・取得・編集を共通の業務処理へ接続する。HTTP/GUIと同じ現在認可・版・操作IDを使い、MCPの操作範囲と外部モデルへの送信方針も確認する。

MCP Host、モデル推論、未実装Domainの仮tool、任意SQL・graph更新・shell・mergeの公開、MCP Samplingは対象外。既存の共通UIで行えるContext編集を比較対象とし、後続Issueの本編集GUIやLLM操作を実装済みとは数えない。

## 有限な確認条件

IssueのAC-1〜6とINVAR-1〜5を維持し、次のfixtureで判定する。新たな利用者体験や制限が必要になった場合は、実装しながら追加せず、AGENTS.md §4に従って判断を得る。

| 条件 | 対象・期待結果 | 判定方法 |
| --- | --- | --- |
| AC-1 | Oryと固定したSDK/仕様で発見・metadata・client登録・resource指定からStreamable HTTPへ接続 | TLS上の実Oryと実SDK clientで正常フロー、別resource、期限切れ、ID Tokenの拒否を確認 |
| AC-2 | 同じ利用者のGUI/HTTP/MCPが同じ認可・元版・操作IDでContextを参照・編集 | 正例、同一版の競合、応答喪失後の同じ要求の再送を比較し、保存版と履歴数が一致することを確認 |
| AC-3 | 他Workspace・許可外tool/範囲・対象Runのnone/excludeを迂回できない | 2 Workspace・複数Userと、操作別/Run別の固定範囲を用意。tools/resources・別操作ID・再接続で拒否を照合 |
| AC-4 | 検索候補と本文取得を分け、範囲・継続・位置・完全性を返す | 実Bleve/ArcadeDBの上限・部分結果・遅延・必要版欠落・基準位置不一致を再現し、SoT照合とManifest確定可否を比較 |

INVARは、GUI/MCP/HTTPの業務処理の共用、モデル通信と業務操作の分離、編集から実行権限を導かないこと、閲覧権限と外部送信可能範囲の別検証、本文/ログから方針を変更しないことである。C検品では全条件と共通処理の回帰を固定commitで確認する。

## ユーザーが指定した前提と方針

2026-10-16、ユーザーから、膨大なContextを初期から管理することと、送信禁止の情報を分類・管理する方針が示された。[AGENTS.md](../../AGENTS.md)の「プロダクトの前提」にも記載した。

管理者・操作者がContextを逐一選択・許可する案と、送信可の範囲を操作ごとに手動で列挙する案は撤回する。送信してはいけない情報を分類・規則で管理し、検索・探索・取得に自動適用する。件数に比例する許可作業を通常利用の条件にしない。現在の閲覧権限、Runのnone/exclude、操作の目的に応じた範囲は引き続き検証する。

分類・規則の管理と通常のMCP操作を分ける。Contextの一括管理、既存の分類・Scope・属性との対応、規則変更の適用、検索や探索の継続にも禁止対象が混入しないことを設計へ反映する。少数の対象だけでなく、合意した規模で処理量と操作負担を確認する。具体的な分類schemaや管理操作を決定済みとは扱わない。

初期対象は設計書§6.10のkoujou-san自身のクライアントとする。同梱クライアントはセットアップ時の事前登録で接続し、外部MCPアプリの自己登録は今回の対象へ追加しない。OAuthログインとWorkspace権限の確認は別に必須とする。

## 先行調査と終了条件

公式Go SDKの公開releaseとGo module metadataで、最新stableはv1.8.0、必要Goは1.25.0と確認した。現行Go 1.27.2で条件を満たす。依存はまだ追加していない。MCPの2026-07-28仕様には事前登録、Client ID Metadata Documents、互換用途のDynamic Client Registrationがあり、DCRは非推奨とされる。初期は既存の関係がある同梱clientの事前登録を使い、同梱Oryと実clientの対応を確認する。

調査は、ユーザーが選んだ方針のもとでSDK/プロトコル版、Oryのmetadata/resource/scope、tool/resource schema、操作とRunの分離、外部送信範囲、操作履歴を、上記の正常/拒否fixtureへ対応付けた時点で終了する。未実装Domainの将来の登録方法は接続仕様へ残し、仮toolを作らない。

根拠: [Go SDK v1.8.0](https://github.com/modelcontextprotocol/go-sdk/releases/tag/v1.8.0)、[公式SDK](https://github.com/modelcontextprotocol/go-sdk)、[MCP 2026-07-28 client registration](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization/client-registration)。技術上の採用可否は、固定版での実接続後にADRへ記録する。
