## 目的から配置へ

- 値を置く前に、誰が、何を判断するために見るかを一文で決める。判断に結び付かない値は置かない（ガイドブック 2.1、3.2「目的に則する」）。
- 全体を示す値を先に、内訳と詳細を後に置く。三ペインでは中央の一覧・図が全体、右ペインが選んだ対象の詳細を担う（ガイドブック 3.3「構造を伝える」、4.5「全体の指標と詳細のグラフを表示する」）。
- 検索・絞り込みは、影響を受ける一覧の上か左に置く。左サイドバーの絞り込みは中央へ、中央の検索条件はその下の結果へ効く（ガイドブック 3.4）。
- 読み順は左上から右下。先に読む値は見出しの大きさと余白で前に出し、背景色の差では示さない。ガイドブックは左上の背景を変えて目を引くが、面を重ねない方針を優先する（ガイドブック 3.4、[基礎の余白と面](foundations.md#余白と面)）。
- 値を見るために操作を重ねさせない。開いた時点で判断に必要な値が見え、内訳は一度の選択で届く（ガイドブック 3.3「複雑な操作を要求しない」、5.4）。

## 数値と比較

- 数値には単位と時点を付ける。時点は「取得 2026-11-01 09:00」のように取得日時を置き、鮮度を読めるようにする（ガイドブック 3.2「鮮度が高い」、4.4「メタ情報を記載する」）。
- 見出しに値の意味と種別を書く。「費用」ではなく「今月の費用（確定）」「累計トークン」のように、期間・累計・推定の区別を見出しに含める（ガイドブック 4.5「タイトルにグラフの内容とデータ種別を表記する」）。
- 単体では判断できない値には比較対象を添える。前の期間、予算、同じ範囲の平均など、同じ単位・同じ期間・同じ取得範囲のものだけを並べる（ガイドブック 3.3「比較対象を提供する」）。
- 差分は符号付きの数値と文字で示す。費用やトークンの増減は良し悪しではないため、パレットのPositive／Negative色は使わず、成功・失敗色も当てない（パレット「セマンティックカラー」を不採用、[基礎の状態色](foundations.md#ui調整と状態色)）。
- 桁は右揃えと `tabular-nums` で揃え、桁区切りを付ける。確定・推定・未取得・非該当は文字で分け、推定を確定の合計に混ぜない（[パターン3](patterns.md#3-issue優先度と費用)）。
- 値の定義へ届くようにする。何を数えた値か、どの範囲か、いつ更新されたかを、値の近くか詳細ペインに置く（ガイドブック 4.4「データを定義する」）。

## チャートの選び方

図は値を位置や長さに対応させて差と傾向を見せる道具であり、表の代わりではない（ガイドブック 4.1）。見せたいものから種類を選ぶ（ガイドブック 4.2）。

| 見せたいもの         | 種類         | 規則                                                                                          |
| -------------------- | ------------ | --------------------------------------------------------------------------------------------- |
| 時間変化と傾向       | 折れ線       | 横軸は時間だけ。データ点に図形を置き、欠測の区間は線を結ばない。系列名は線の近くに置く        |
| 分類ごとの数量の比較 | 棒           | 原点は0。並び順は数量の大小か更新順など意味のある順にし、列見出しかキャプションで並び順を示す |
| 構成比の時間変化     | 積み上げ面   | 構成比を見せる必要がなければ折れ線。系列が多い、時間変化を見せないなら棒                      |
| 構成比               | 円・ドーナツ | 全体の総量が明らかなときだけ。多くの場合は棒の方が正確に伝わる                                |

- 軸の範囲を恣意的に切らない。省略や拡大で差を誇張しない（ガイドブック 4.4「表現を歪曲しない」、4.5「グラフの原点は原則として0にする」）。
- 下地のグリッド線は最小限にし、3D・影・装飾を使わない（ガイドブック 4.5、[基礎の余白と面](foundations.md#余白と面)）。
- 凡例は図に隣接させ、順序を図の系列と一致させる。凡例・系列名・軸ラベルは短く保つ（ガイドブック 4.5「グラフと凡例を隣接させる」「タイトルや凡例をシンプルに保つ」）。
- 図の値は同じ画面の表か一覧から読めるようにする。図は表の読み方を補うものであり、表を消して図だけにしない（ガイドブック 5.5「データテーブルを公開する」「代替テキストを付与する」）。

## チャートの色と識別

- 色面は背景に対して3:1以上。満たせない色面は、すぐ近くに値を書くか、hover・focusで値を出す（ガイドブック 4.3「コントラスト比の考え方」、DADS 1.4.11）。
- 色数は1〜5色に絞り、注目させる系列を一つ決める（ガイドブック 4.5「グラフに使用する色数を絞る」、5.4）。
- 系列の役割は主・強調・比較対象の三つに分け、既存配色を当てる（パレットの役割名Primary／Secondary／Neutralを採用し、色値は採用しない）。

| 役割             | 色                                | 紙の地 `#f6f5ef` との比 | 使い方                                                  |
| ---------------- | --------------------------------- | ----------------------- | ------------------------------------------------------- |
| 主系列           | green `#183b34`、green2 `#285348` | 11.2、7.9               | 選んだ対象、現在の期間                                  |
| 強調・注目点     | orange `#ba482c`                  | 4.8                     | 予算超過や注目させる一点。失敗の意味には使わない        |
| 比較対象・その他 | muted `#596862`                   | 5.4                     | 前の期間、平均、残りの分類                              |
| 塗りの補助       | lime・wash・peach                 | 1.1〜1.3                | 単独では色面にしない。3:1を満たす輪郭と値の併記を付ける |

- 系列どうしの色の比は3:1に届かない（green／orangeは2.4、green／mutedは2.1）。系列は線種・データ点の形・塗りの模様・直接ラベルで見分けられるようにし、白黒でも読めるようにする（ガイドブック 4.5「色のみで分類を識別しない」、DADS 1.4.1）。
- 色を付ける要素は前景と背景を対で指定する。背景だけ、文字色だけの指定を残さない（DADS「前景色と背景色の両方を指定する」）。
- 選んでいない系列を薄くするとき、無効と見えないように系列名を4.5:1の文字で残す（DADS 1.4.11「グラフ、チャート等のダイヤグラム画像の場合」）。
- 多色にするときは色覚シミュレーションで見分けを確認する（ガイドブック 4.3「色覚多様性の考慮」）。

## 欠測・未取得・鮮度

- 欠測を0にしない。折れ線は区間を空け、棒は欄を空けて「未取得」と書く。合計・平均は欠けた範囲を明記する（ガイドブック 2.2「データの制約」、[部品の通知](components.md)「不完全」）。
- 取得中は既取得の値と図を残し、取得中の範囲だけを文字で示す。図全体を消したり、仮の値で埋めたりしない（[部品の一覧・表](components.md)）。
- 分解できない粒度を図で見せない。日次のデータしかないものを時刻の図にしない（ガイドブック 2.2「必要な分解能がない」、3.2「分解できる」）。
- 比較できない値を同じ軸に載せない。単位・期間・取得範囲が違う値は別の図か別の列に置く（ガイドブック 2.2「指標同士を比較できない」）。

## 表と一覧

- 並び順に意味を持たせ、どの列で並べたかを示す。既定は更新順か数量の大小（ガイドブック 4.5「グラフ項目の並び順に意味を持たせる」）。
- 数値列は右揃え、文字列は左揃え、単位は列見出しに置く。同じ列に単位の違う値を混ぜない（[基礎の書体](foundations.md#書体と文字階層)）。
- 行はそのページの抜粋であることを件数と取得位置で示し、全件の合計と見せない（[入口の前提](../../DESIGN.md)）。
- 判断に関わらないメタ情報は補足の文字階層に落とし、値と同じ強さで並べない。薄くしても4.5:1を保つ（ガイドブック 4.5「不要な要素は削除する」、DADS「コントラスト要件」）。

## 余白と視線

- 一画面に置く値と図の数を目的に合わせて絞り、余白を埋めるために増やさない（ガイドブック 3.3「適切な情報量にする」、[基礎の幅と読み順](foundations.md#幅と読み順)）。
- 強弱は一か所に集める。重要な値だけに大きさ・太さ・色の差を与え、全部を強調しない（ガイドブック 4.4「強弱をつける」）。
- 骨格を先に決め、表層を後で詰める。配置が決まる前に色や図の表現を細かく調整しない（ガイドブック 3.3）。
