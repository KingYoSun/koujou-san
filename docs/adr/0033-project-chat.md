# 0033: Projectの永続チャットと既存操作への接続

- 状態: Accepted
- 日付: 2026-10-31
- 根拠: Issue #82、設計書§4・6.10・7・8・10・12、ADR 0026。

## 保存と権限

Projectは既存の`project` Scopeを使う。スレッド、メッセージ、関連作業への参照を既存`client_operation_records`へ保存し、共有の版・要求ID・receipt・現在権限を使う。スレッドの参照にProjectを含め、メッセージと操作は元スレッドおよび必要な参照元の認可を引き継ぐ。モデルの文面を実行結果や検品判定として保存しない。

一覧と会話はProject・スレッドを条件にページ取得する。モデルへ送る履歴は選んだ固定メッセージと今回の依頼に限定する。必要なContextは既存のScope・検索・ページ継続で選ぶ。全Workspaceや全会話の取得・送信を前提にしない。

## モデル送信と復帰

会話の応答を`clientops`の操作として扱い、接続の固定版、送信意図、原応答、実モデル名、usageを既存処理で記録する。資格情報とHTTPは従来どおり依頼者のクライアントが所有する。会話本文へキーや認証tokenを複製しない。モデル応答の完了前は進行中として表示し、不完全な応答・失敗・結果不明を完了へ変換しない。

画面を開き直した際は現在の保存状態を取得する。送信済みの結果不明操作を閲覧・再接続だけで再送しない。チャットのための常駐AI、モデルサーバー中継、実行エンジンは追加しない。開始済みRunは既存Runnerが継続する。

## 仕様の採用と作業

メッセージの固定版と採用範囲を指定して、既存Context保存へつなぐ。由来に元メッセージの版・digest・範囲を記録する。Contextの文書構造、Projectへの所属、Runへの注入を分ける。

定義生成、Context選択、Run・工程の開始依頼、Pause回答は既存サービスを呼ぶ。保存と開始を分け、必要な入力と版を確定する。チャットの自由文に書込み権限を与えず、既存の許可済み方針へ追加の一律承認を加えない。独立検品には固定成果物と選んだ条件を渡し、会話全文や実装者の自己評価を自動注入しない。

## 選定理由

専用の保存・モデルループ・実行処理を別々に作ると、認可・要求ID・費用計測・復帰処理が重複する。既存の操作記録と各業務サービスを使い、会話に必要な保存と操作の接続だけを加える。
