# Issue #6: Workspace参加・権限と端末の資格情報

- 対象: Issue #6、Scope revision 1、区分C。
- 基準: #5をマージした0eeee997d5365ad9db1b7af35452102b2f3b12fa。
- 現在の判定はcurrent-state.mdへ集約する。

## 目的と範囲

認証済みUserをWorkspaceのMemberへ対応付け、招待・役割・所属変更・利用停止とDeviceの登録・許可範囲・更新・失効を保存する。利用者の操作とRunnerの報告を別の主体で認可し、Web/Tauri共通UIで現在の権限と最後に観測した接続状態を示す。

CLI起動、Run割当世代の確定、プロセス停止、大規模組織向け権限、企業SSOは対象外。Contextや検索の実装を先取りせず、今回は共通認可の対象解決と操作表をfixtureで検証する。後続のContext・検索・MCP接続は同じ認可処理へ接続する。

## 固定する条件と確認

| 条件 | 対象と期待結果 | 判定方法 |
| --- | --- | --- |
| AC-1 | 新規Workspaceと招待受諾。認証だけでは既存Workspaceへ参加しない | 実DB・2アカウントで作成、正しい宛先と無効な招待、未参加アクセスをAPI/Web/Tauriで照合 |
| AC-2 | 別Workspace・権限のないContextの読取/更新/検索/取得/実行依頼を拒否。包含・Scope所属で広げない | 2 Workspaceとリソースの認可表でID差替え・参照/所属の負例を共通認可へ通す |
| AC-3 | 閲覧/編集Memberと登録端末にcommand実行を暗黙に許可しない | 読取/編集/実行依頼の独立した許可表とUIの権限表示を照合。CLIは起動しない |
| AC-4 | Deviceは許可されたWorkspaceと担当対象の報告/入力取得だけを行う | 正常な報告/入力取得、User偽装、他端末/他対象/権限変更をAPIで比較 |
| AC-5 | 権限取消・離脱・Device失効後は新しい操作を拒否。切断CLIを停止済みと表示しない | 取消前後の同じ要求、再送とUIの最後の報告・失効表示を照合 |
| AC-6 | 登録者離脱時の採用方針を適用し、Device秘密値を同期しない | 離脱・再登録・更新・失効をWindows実機で確認し、共有応答/更新記録/ログを照合 |

INVAR-1〜4はIssue本文を維持する。UIだけで認可せず、権限取消と停止を分け、秘密値をチームへ同期しない。共通の業務認可をGUI・HTTPと後続MCPの境界で再利用する。

## 実装の順序と予定path

1. 下記の利用者に見える方針を確定し、有限の認可表とADRを置く。合意済みの権限・実行分離は変えない。
2. `apps/server/internal/access/`と追加migrationでWorkspace/Member/Invite/Device/許可範囲/資格情報hashを扱う。#4の版・更新記録・認可後の再送確認へつなぐ。現在のGrantは内部型であり、clientから許可を受け取らない。
3. #5の認証済みUserから利用者主体を構成する。Deviceは別資格情報で主体を構成し、割当対象と操作範囲を照合する。資格情報の秘密値は共有DTOへ含めない。
4. 共通UIのチーム・端末管理と、Windowsのローカル保存・更新・失効をつなぐ。表示には最終観測時刻を使い、実プロセス停止を主張しない。
5. 実DB・二つのWorkspace・複数役割/端末の認可表、Web/Tauriの実操作、固定commitの区分C独立検品、CI、マージ後照合を終える。

## 判断待ちと調査の終了条件

AGENTS.md §4に従い、初期Workspaceを作成できる人、初期の役割と実行許可、招待受諾条件、登録者離脱時の共有端末の扱いはユーザーの判断を待つ。これらに依存するschema・UIを先に確定しない。

資格情報の具体的な形式・hash・Windows保存領域・更新方式と失効の反映時間は、採用方針の範囲で接続試作する。正常/失効/更新/対象差替えのfixtureが有界に判定でき、秘密値の経路と運用をADRへ記録した時点で調査を終える。新しい利用場面を追加して完了を延ばさない。

DESIGN.mdとdocs/adr/0014-uiux-dev-flow.mdは#5開始時には未提供だった。作業時に存在を再確認し、存在しなければ設計書§5.2・12.1〜12.3と共通UIを根拠にする。
