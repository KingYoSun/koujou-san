# Projectのチャット

「作業」の「Projectチャット」で本文を入力し、「送信」すると相談を開始する。最初の送信でスレッドを作り、本文の冒頭から題名を付ける。IssueやRunは不要。会話は共有APIへ保存され、同じProjectを参照できるメンバーが取得できる。

再訪時は同じAPI・利用者・WorkspaceのProject、相談、モデル接続を復元する。初回は取得ページの先頭のProjectと利用可能なモデルを表示する。Project名とモデル名から切り替えられる。「新しい相談」で本文が空の入力欄へ戻り、最初の送信まで共有スレッドは作らない。

Projectがない場合は「Projectを作成」からScope作成画面を開く。Project名と自由入力、または `.txt`・`.md`・`.html` から[初期ContextとProjectを保存](context-ui.md#文書を組み立てる)できる。空のProjectだけを作る場合は、作成種別がProjectになっている状態で新規作成し、下書きを共有保存する。「Projectで相談」から同じ固定版のProjectを開き、相談を作れる。Project名による検索はサーバーでProjectだけに絞り、100件ずつ取得する。Projectからはリポジトリ設定と共有設定へ進める。

画面は左にProject切替と相談履歴、中央に会話と入力欄を置く。狭い画面では「相談履歴」を折りたたむ。返答の見出し・表・コード・強調・リンクはMarkdownとして表示する。会話は最新が下で、新着時は最下部へ追従し、上へ戻って読んでいる間は追従せず「最新のメッセージへ」で戻る。チャット以外の画面では右下の「Projectチャット」から同じチャットをpopoverで開ける。popover内で相談を開いても画面は移動せず、「チャット画面で開く」で同じ相談を中央に表示する。

## 相談とモデル接続

「保存のみ」は人間の発言を保存する。「送信」は、発言の保存後に表示中のモデル接続へ相談を送る。Ctrl+Enterでも送信できる。既存の[接続設定](client-context-selection.md)を使い、WindowsのChatGPTサブスク接続は提供元へログインしてから使う。キーやOAuth tokenを会話に入力しない。

Webではモデル選択の「サーバー接続を再取得」から、サーバーに登録済みの接続を利用できる。サーバーに認証情報を保持したままモデルへ中継し、対話とContext読取りは既存のクライアントHostが進める。登録・認証や、クライアント不在時の対話継続をWebへ追加するものではない。

次の相談へ含める過去の発言はチェックで選ぶ。今回の入力と選んだ固定版だけを送る。「Context・設定・登録ファイルを参照」を選ぶと、モデルはProjectのContext検索・固定版取得、登録設定と実行状態の確認、登録リポジトリのファイル参照を利用できる。外すとこれらを参照しない。Workspace全件や会話全文を取得・送信する前提にしない。

「開発の準備を確認する」から相談文を入力できる。モデルは `project_inspect` で本人の実行権限、選択モデル、Projectの登録リポジトリ、WorkspaceのRunner・Runの取得ページを確認する。`repository_read` はProjectに関連付けたGitea登録先のcommitを固定し、一覧は50件、本文は32KiBずつ必要な範囲を読む。参照URL・commit・pathを根拠にし、取得不能や未確認を設定済みと扱わない。端末の未commitファイルはこの参照結果に含まれない。不足設定は「Projectの設定」からリポジトリ接続、CLI・Runner、端末・共有ポリシーへ進む。

履歴と相談一覧は50件ずつ取得する。会話は新しい取得ページから表示し、「以前の会話を表示」で前へ進む。接続の確認中、情報の取得中、返答の作成中、未完了、失敗、結果不明を区別する。メッセージの「詳細・仕様に採用」で、固定版、採用範囲の選択、モデル操作の原応答を右の詳細ペインに表示する。利用量は操作へ帰属し、実装Runの費用には重ねない。

## 仕様の採用と作業

完了した発言の「仕様として採用する範囲」で本文を選択するか、メッセージ全体を指定する。「この範囲をContextに保存」で、元メッセージの固定版・digest・UTF-8範囲を由来に持つSentenceを保存する。Projectへの所属も保存する。保存後のContextは通常の編集・選択・プレビューを使う。

採用記録の「この仕様でRun定義を準備」で工程画面へ進む。採用したContextを選択した下書きから、既存の定義生成・編集・検証・採用を使う。定義の保存とRunの作成、割当・開始依頼は別の操作である。入力と対象版を確認してから依頼する。会話全文や前Runの出力を自動注入しない。

「既存のIssue・Run・工程を関連付ける」から、取得ページの対象を名前で選べる。関連Runは現在の実行・観測・検品状態と質問を取得する。回答には既存の回答欄を使い、API受付・配送・再開を別々に確認する。原出力や固定成果物、CI、検品の根拠は関連作業から辿る。AIの説明で実行や検品PASSを確定しない。

## 再訪と結果不明

Projectの情報を参照する場合は、入力欄の「Project参照」から「MCPへ接続」で専用の認証を行う。通常のアプリへのログインとは別の資格情報を使う。現在の本人と認証状態を確認して「認証済み」「未接続」「別アカウント」を表示する。認証済みは設定やファイルの取得成功を意味せず、実際の参照は送信した相談の中で行う。

自分の操作には「このクライアントへ引き継ぐ」「相談を再開」「相談を続ける」「この相談操作を終了」が状態に応じて表示される。再開・継続には、その操作と同じ接続・版・モデルを選ぶ。別の接続を使う場合は接続を選んで引き継ぐ。送信中の結果不明は自動再送せず、保存した原応答の確認と明示的な終了を使う。

会話や関連先から戻ると、同じスレッドを再取得できる。モデル要求の結果が不明なときも、再読込や画面の再表示だけでは再送しない。保存操作の再確認は同じ要求IDと元版を使う。開始済みRunは、画面とは独立した既存Runnerが継続する。

閲覧、保存、送信時には現在のWorkspace・Project・参照元の権限を確認する。失効時には表示を再取得し、以前に見えていた記録を現在の許可として扱わない。

## 検証

`pnpm run test:clientops`で共有保存、採用範囲、認可、モデル送信意図、応答喪失と利用量を確認する。`pnpm run test:chat:ui`は実Ory、1万Context×3版、60件の会話と管理下のモデルHTTPを使う専用環境を起動する。試験用アカウントと不活性キーだけを使う。実モデルの確認とは区別する。
