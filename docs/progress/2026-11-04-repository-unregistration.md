# リポジトリの登録解除を共通化する

## 目的と境界

基準commitは`d37bba5b`。ユーザーは、作成拒否に限った削除を、設定したすべてのリポジトリの登録解除へ統一する方針を承認した。リポジトリ設定一覧と新規選択候補から外し、Gitea上の本体、保存済みID、Run・Workflow等の参照、共有履歴と送信履歴を保持する。

既存の共有削除フラグを登録の有無の正本とし、リポジトリ情報の行は残す。状態別の削除処理と物理削除を撤去する。既存IDによる参照・既に保存した連携は維持し、権限の失効や進行中の実行の停止とは扱わない。まだ送信していない作成要求を登録解除後に再送せず、送信済み要求の結果は履歴へ残して一覧に戻さない。外部repoの削除、共有資格情報の削除、登録復元の画面、Run・Workflow等の書換えは対象外。

既存の`POST /repositories/{id}/delete`は維持し、同じ操作を全状態へ広げる。APIの重複経路は作らない。保存済みリポジトリ情報とJSONの形は維持する。解除済みを大量に取得しないよう、共有状態の有効なrepo登録だけを扱う部分indexを追加する。既存migrationは変更しない。

## UIの判断

Workspace管理者が、選択した登録を新規利用の一覧から外すか判断する。中央の一覧は現在の登録、既存フォームは選択対象の詳細を示す。すべての保存済み記録に「リポジトリの登録を解除」を表示し、操作後は対象と選択フォームを消す。未保存フォームには表示しない。作成拒否専用の文言と条件を撤去し、既存の通知・secondaryボタンを使う。

## 受入条件

| 条件 | 対象と期待結果 | 判定方法 |
| --- | --- | --- |
| AC-U1 | 登録済み・作成済み・存在確認済み・作成拒否・送信意図・結果未確認のすべてを同じ操作で登録解除でき、再取得でも一覧と新規選択候補から外れる | 各状態の専用DB API試験、既存の外部起票候補・共通pickerの経路、実フォームで成功記録と拒否記録を解除して再取得 |
| AC-U2 | 過去のIDと情報、Run・Workflow等が持つ参照、保存済みの外部連携、共有履歴とreceiptを保持し、Giteaへの削除要求を送らない | 解除前後の保存情報・既存IDの読取りと連携解決・既存履歴・所有HTTP要求数、参照元のコードを照合 |
| AC-U3 | 未送信の作成要求の再送を防ぎ、送信済み要求の結果が解除後に返っても記録し、候補へ再表示しない。解除済みを古い設定保存で復活させない | 送信前の意図、応答を保留した所有HTTP、古い作成receiptと版、解除後の保存試験 |
| AC-U4 | 管理者・対象更新権限・現在版の条件を維持し、同じ解除要求の再送は同じ結果を返す。50件のページ取得と解除済みを除くindex経路を維持する | 既存の権限・版・receipt試験、migrationとSQL・ページ試験を照合 |
| AC-U5 | 状態別の削除UIをなくし、保存済みの各対象に共通操作を表示する。1440px・1024pxで文字切れ、重なり、横スクロール、focusの欠落がない | 静的描画・実フォーム、配備後の通常UIで各対象選択と両幅の実表示確認 |

## 実装・検証と終了

保存・認可・migrationに関わる区分C。削除専用の分岐と試験を共通登録解除へ置き換え、物理削除と新旧APIの併存を残さない。`test:forge`、共通UIの対象試験、`check`、migrationを含む必須CIと固定commitの独立検品を行う。受入条件を満たしたら終了し、解除を権限失効や外部削除へ広げない。文書はyomiyasuで推敲する。配備と実表示を含む現在の判定は、この記録を参照するPRの結果欄へ集約する。
