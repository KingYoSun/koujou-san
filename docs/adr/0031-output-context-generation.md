# ADR 0031: 固定出力からのContext生成と版付き反映

状態: Accepted。Issue #31。初期の自動反映と明示有効化は2026-10-18に本人が承認した。

## 共通の生成操作

既存Host/clientopsへ `context-generation` を追加する。送信意図、原応答、質問と回答、本人の引継ぎ、再送照合、モデル/usage/単価、操作上限を共用する。手動と自動生成で同じHostと通信入口を使う。

元Runとoutputの固定版、対象箇所のJSON pathを指定する。別のoutputやPauseの回答を使う場合も固定参照と箇所を指定する。モデルの `run_get` は指定した箇所だけを返す。既存Contextは通常の検索・Scope・関係探索と固定版取得で絞る。noneでは既存Contextのtoolを使えず、元出力の権限確認用の依存参照からContext本文の取得権限を増やさない。

モデル応答は `changes_utf8 / reason / questions / unknown` を持つ。変更案はContextの作成/新版、順序付き構成、所属、再利用/重複/矛盾候補を分ける。モデルの類似判断だけで統合・削除しない。採用対象の変更を選び、既存contexts serviceの同一transactionで検証・保存する。元版競合や未選択の必要な子があれば一括反映を保留する。

新規ContextのIDは変更案のkeyと生成操作IDからサーバーが決める。四粒度の子から親の順に固定版を作り、同時作成参照を解決する。由来はサーバーが元outputのID/版/digest/箇所と生成操作IDから付ける。モデルによる採用では、指定箇所のMCP取得記録を照合する。本人が明示的に修正した案は別の履歴へ保存し、同じContext検証と現在の編集権限で採用する。

## 状態・由来・境界

元出力にある観測、モデルの推測、採用する判断、未確認の提案を別の状態として記録する。自己申告を独立検品PASSへ変換しない。生成操作、参照したContext版と元出力を、Contextの固定版ごとの由来記録から追う。由来の取得と生成結果の一覧は索引とページを使い、Workspace全体の本文/IDを読み込まない。

モデルによる既存の分類tags変更を拒否する。手動固定した値はモデルへ送らず保存前に照合する。原出力・過去判定・開始済みRunのinput/Manifestは更新しない。新Contextを後段へ渡すときは通常の基準版への明示採用と選択を使う。

## 自動生成

生成方針の保存と有効化を分ける。担当する本人のクライアントとモデル接続を明示し、有効化後にRunの終了を受理したとき、指定チャンネルの固定出力をページで処理する。Context更新だけでは次の生成を始めない。Runを構成するノードは増やさない。

方針版と固定outputの組から操作IDを決め、通知/受領応答の再送や過去分の再照合でモデル要求・反映を重複させない。クライアント終了や結果不明の要求は共通の送信意図へ残す。画面を開いたクライアントだけがモデルへ要求し、サーバーは要求と状態を保存する。無効化・有効版変更後の新しいモデル要求と自動採用を止め、原応答は履歴へ保持する。

過去分は日時と有効方針版を指定した別の依頼で照合する。Runの確定位置とIDの上限を固定し、キーで50件ずつ取得する。Source/Contextの全件配列を組み立てない。

## 保存と互換性

migration 24に、由来の直接取得、方針の対象索引、出力待ちと過去分照合の保存を追加する。既存のContext本文・Origin・構成・所属・inputの保存形式を維持する。既存migrationのdigestは変更しない。DBの通常のbackup/restoreに含める。標準配布の更新試験は現在bundleのschema番号で検証する。
