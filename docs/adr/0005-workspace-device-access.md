# 0005: Workspace参加と端末の認可

- 状態: Accepted
- 日付: 2026-10-15
- 対象: Issue #6、設計書§6.3・6.4・12.1〜12.3、[計画](../progress/2026-10-15-issue-6-plan.md)

## 採用した方針

メール確認済みUserは新しいWorkspaceを作成でき、そのWorkspaceの管理者になる。既存Workspaceの所属は自動で与えない。ユーザー判断により、招待はログイン済みのリンク所持者が受諾できる。宛先メールには結び付けず、転送先も参加できる。招待は一回の受諾で使用済みとし、期限と取消を照合する。

| 操作 | 閲覧者 | 編集者 | 管理者 |
| --- | --- | --- | --- |
| Workspaceと許可されたリソースの閲覧 | 可 | 可 | 可 |
| 許可されたリソースの編集 | 不可 | 可 | 可 |
| 招待・役割・所属の管理、端末許可の変更 | 不可 | 不可 | 可 |
| 自身の離脱 | 可 | 可 | 可 |
| 自身の端末の登録・更新 | 不可 | 可 | 可 |
| 実行依頼 | 別の明示許可が必要 | 別の明示許可が必要 | 別の明示許可が必要 |

実行許可の初期値は不許可。端末登録から実行許可を導かない。Workspaceの役割と、制限されたリソースへの許可も別に照合する。包含・参照・Scope所属を権限の根拠にしない。Context本文・検索・Runを本Issueで先取りせず、対象の所有Workspaceと制限・担当端末を共通認可へ渡す境界を実DB fixtureで確認する。

## 端末と失効

端末の識別子と登録者を記録し、Workspaceごとの登録・許可を分ける。資格情報でできる操作は、許可されたWorkspaceと担当対象への入力取得・報告に限る。利用者の偽装、メンバー管理、任意対象への更新は許可しない。最終接続時刻を記録するが、CLIの稼働・停止を保証する値として扱わない。

登録者がWorkspaceを離脱・利用停止した場合、そのWorkspaceの端末許可を失効する。他Workspaceの登録は維持する。利用者のログアウト、Workspaceの所属取消、端末資格情報の失効、CLI停止は別の状態である。取消・更新後の次の要求から現在のDBを照合し、開始済みの切断中CLIを停止済みと表示しない。

招待リンクの証明と端末の秘密値は用途を分けたHMACで導出する。端末の更新では導出用の世代を替え、旧資格情報を拒否する。元の鍵はGoの安全な環境設定に置き、資格情報の値はDB・共有更新記録・receiptへ保存しない。私的な発行応答は認可後に組み立て、再送でも共有receiptへ秘密値を混ぜない。WindowsではDPAPIで保持し、共通UIへ渡さない。

## 保存と確認

認可はAPI要求ごとに現在の所属・役割・リソース・端末許可を照合する。Workspaceの更新では共有streamのロック後にも再確認し、権限取消後に過去のreceiptだけで要求を成功させない。DB更新、版、秘密値を除いた更新記録とreceiptは#4の同じtransactionで確定する。

具体的な成功・拒否・失効・再送とWeb/Windowsの観測は本Issueの検証記録へ残す。APIに存在しないContext・Runの本体を、この認可fixtureの成功だけで実装済みとは扱わない。
