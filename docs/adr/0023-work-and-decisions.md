# 0023: 作業と判断の共通画面

- 状態: 実装・受入検証中。
- 日付: 2026-10-17。
- 根拠: Issue #23、[計画](../progress/2026-10-17-issue-23-plan.md)。

## 一覧と選択した作業

ユーザー判断に従い、Workspace内の「作業と判断」へ一覧・詳細・回答の入口をまとめる。既存Runと工程実行の現在版から小さな一覧を作り、新しい作業状態や実行エンジンを追加しない。一覧は名前・工程・実行/観測/判定・待機理由・担当・次操作を持つページとする。入力本文・Context・原ログは一覧へ含めない。

選択した作業だけから質問、固定成果物、検品時の条件、現在の判定適用範囲、証拠を取得する。入力メタデータの取得でもContext本文を読まず、本文と原出力は既存の明示操作で取得する。技術情報は展開できる。大量のContextや全履歴を取得してクライアントで結合する方式は採用しない。

## 質問、回付、差し戻し

Pauseのrequestは既存の任意JSONを維持する。質問・背景・確認操作・選択肢と影響・待つ工程を持つ値は構造化して表示し、自由文や既存JSONも読めるようにする。人の検品は同じPause回答入口で判断・理由・証拠を入力できる。回答案の端末保存、API受付、Runner配送、継続確認を分け、再接続だけで送信しない。

回付と理由付き差し戻しは、固定Runまたは工程実行に付く補足記録とする。migration 019の索引付き記録へ共通CAS/receiptで保存し、回答や実行状態を複製しない。回付先にも現在の閲覧・回答権限を確認し、指名で権限を付与しない。本文・対象・条件・問題・期待結果を保存してもcommandを起動しない。

修正・再検品は既存の新Run作成と関連元の固定参照を使う。補足記録に別のRun関連モデルを作らず、旧入力・原出力・判定を保持する。閲覧履歴と補足記録を入力へ暗黙に取り込まない。

現在権限と参照は保存transaction内でも共通の`SourcesTx`で確認する。別接続から同じWorkspaceの更新を待ちながら読取りを行う構成にしない。非公開の回付は一覧の担当表示や自分向け絞込みへも露出させない。

## 互換性と検証

既存APIの出力と保存形式、適用済みmigration 001〜018は変更しない。共通画面の一覧キャッシュは主体・API・Workspace別の既存保存へ置き、アクセス失効・ログアウトでは既存の削除方針に従う。

区分Cとして共有PG、状態別UI試験、実Oryと二アカウントの共通画面、実CLIの試験用接続、固定成果物の独立検品で確認する。OS起動・認証・スリープの実機操作は繰り返さない。背景を知らない参加者の操作はAIの自己評価で代替しない。実施範囲と未確認は[証跡](../progress/2026-10-17-issue-23-evidence.md)へ記録する。
