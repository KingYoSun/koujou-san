# 0011: Context単位のローカル保存と対象の同期

- 状態: Accepted
- 日付: 2026-10-16
- 対象: Issue #12、設計書§5.2・§8・§11、ユーザーの移行方針への回答
- 置換する範囲: [ADR 0007](0007-shared-sync.md)の共通GUIの全体snapshot/差分追跡とWorkspace一括保存。既存HTTP APIと実行報告の契約は維持する。

## 判断

共通GUIはBleveの候補メタデータ、Scope一覧、固定版履歴、ArcadeDBの関係をページで取得する。本文は開いた対象で取得する。Zustandは画面の選択、TanStack Queryは共有表示、同期エンジンは編集の基準版・下書き・未確認要求を担当する。

WebはIndexedDBのレコード、WindowsはWorkspaceごとのSQLiteのレコードへ保存する。Windowsの本文・下書き・同期ヘッダーはDPAPIで保護する。各レコードはAPI・User・Workspaceへ結び付ける。一件の編集で他のContextを書き直さない。

ユーザーが承認した方針に従い、旧Workspace一括データを移行する。本文、下書きの基準版と値、未確認の操作IDと要求、競合、receiptを保持する。移行と完了記録は同じトランザクションで確定し、失敗時は元のデータから再試行する。移行後は旧版アプリと混在させない。

共通GUIの定期同期は`pull`の`watch`を使う。表示・編集対象を100件ずつ照合し、版が同じ本文は返さない。無関係なWorkspaceの変更履歴は追わない。旧snapshot/changesは互換用の業務APIとして残す。実行報告も現在の対象権限を照合し、実行結果の成功へ置き換えない。

## 保持する境界

再接続しても下書きを自動送信しない。送信前に操作ID・前提版・内容を保存し、応答不明では同じ要求を再送する。競合への再適用は利用者が差分を確認した後に行う。保存・所属変更・入力プレビューからRunやCLIを開始しない。

サインアウト・権限失効を確認した対象の本文と下書きを削除する。取得中だったローカルキャッシュからも復活させない。権限の確認状態が変わった入力プレビューは再確認を必要とする。

## 選定理由と検証

Workspace一括保存では、一件の編集でも全本文を複製して再保存していた。レコードと索引を使う構成へ置き換え、旧画面の編集経路を残さず共通GUIへ接続する。移行・失敗後の再試行・再起動・権限失効・実画面の証拠は[検証記録](../progress/2026-10-16-issue-12-evidence.md)を参照する。
