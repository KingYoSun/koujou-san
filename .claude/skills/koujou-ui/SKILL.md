## 着手前に三行で決める

実装前に次を書き出し、受入条件へ入れる。書けない項目があれば、ユーザーへ選択肢を示して判断を得る（AGENTS.md 作業原則4）。

1. 誰が、この画面・値を見て何を判断するか。
2. 全体を示すものは何で、内訳・詳細は何か。中央と右ペインのどちらに置くか。
3. 変わる操作・表示・互換性は何か。減る表示や文言があれば列挙する。

## 確認項目

### 配置とレイアウト

- 三ペインの責務を守る。左サイドバーは画面一覧と対象一覧・絞り込み、中央は現在の画面と全体、右ペインは選んだ対象の詳細。右ペインは内容がないとき出さない。
- 絞り込みは影響を受ける一覧の上か左。読み順は左上から右下、全体から内訳へ。
- 1120pxより狭い幅では画面選択のselectと縦積みに切り替わる。ページ全体に横スクロールを作らず、表やノード図の横スクロールはその領域に限定する。
- 先に読む値は見出しの大きさと余白で前に出す。面を重ねたカード、背景色の差、影で目立たせない。
- 非表示の画面のフォームをDOMへ常設しない。訪問済み画面の状態は保持する。

### 文言

- 説明ではなく構造で示す。見出し・札・矢印のラベル・折りたたみで伝え、操作方法や製品の前提を述べる段落、入力のhint、値の後ろの補足文を置かない。
- 残す文は状態・結果・エラー・権限不足・空表示だけ。短くし、対象を明記する（「次のページを取得できませんでした」）。
- ボタンは日本語の動詞＋対象で結果を明示する。定義保存、クライアントLLM操作、Run開始を一つの「実行」にまとめない。

### 数値と比較

- 単位と取得時点を付ける。見出しに期間・累計・確定か推定かを含める。
- 比較対象は同じ単位・同じ期間・同じ取得範囲のものだけ。差分は符号付きの数値で示し、増減に成功・失敗色を当てない。
- 右揃えと `tabular-nums`、桁区切り。確定・推定・未取得・非該当を文字で分け、推定を確定の合計に混ぜない。
- 行はページの抜粋。件数と取得位置を示し、全件の合計と見せない。

### チャート

- 種類は見せたいものから選ぶ。時間変化は折れ線、数量比較は棒、構成比の時間変化は積み上げ面、円は総量が明らかなときだけ。
- 原点は0、軸を恣意的に切らない。グリッド線は最小限、3D・影・装飾なし。
- 色は主系列green、強調orange、比較対象mutedの最大5色。lime・wash・peachは単独の色面にしない。
- 系列どうしは色の比が3:1に届かないので、線種・データ点の形・模様・直接ラベルで見分けられるようにする。凡例は図に隣接させ、順序を揃える。
- 図の値は同じ画面の表か一覧からも読めるようにする。欠測は線を結ばず「未取得」と書く。

### 状態・色・アクセシビリティ

- 状態は文字＋記号＋必要な色。色だけで意味を示さない。「判断不能」「未取得」を失敗色にしない。
- 文字はサイズを問わず4.5:1以上、操作境界・focus枠・チャートの色面は隣接色と3:1以上。色を付ける要素は前景と背景を対で指定する。
- 新しいCSS変数の体系やテーマを増やさない。既存の変数と `foundations.md` の値を使う。
- 取得中は既取得の内容を残し、取得中の範囲だけを文字で示す。

## やらないこと

- 操作説明の段落、入力のhint、副ラベル・補足文の追加。
- 色だけで系列・状態・増減を示すこと。増減へのPositive／Negative色。
- 全画面ダークテーマ、巨大なヒーロー、ロゴの決定、新しいテーマパッケージ・フォントCDN・UIフレームワーク・Storybook。
- 全件のカード表示、一件ずつの許可、全件取得を前提にした集計や図。
- 余白を埋めるための値・図・カードの追加。依頼されていない画面や機能の追加。
- デジタル庁の7色パレットやPower BIテンプレートの色値・16:9グリッドの持ち込み。配色は既存の深緑・ライム・赤茶を優先する。

## 確認手順

1. 静的描画テスト。対象画面の `*.test.tsx` に `renderToStaticMarkup` で文言と構造（見出し、札、aria属性、空表示）を固定する。削除した説明文を前提にしたテストは同じ作業で更新する。
2. 型検査とテスト。
   ```powershell
   pnpm --filter @koujou-san/client run check
   pnpm --filter @koujou-san/client run test
   ```
3. 実表示。1440px（三ペイン）と1024px（select＋縦積み）で、文字切れ・重なり・ページ全体の横スクロール（`scrollWidth === clientWidth`）・focus枠・右ペインの出し入れを見る。認証済み環境は `pnpm run test:<領域>:ui` の固定環境を使い、使えない場合は固定データのプレビューで確認してその事実を記録する。
4. 色の確認。新しい色の組合せを足したら、前景と背景の比を計算して4.5:1／3:1を記録する。多色の図は色覚シミュレーションで見分けを確認する。
5. 整形。
   ```powershell
   pnpm run format:check
   git diff --check
   ```
6. 記録。`docs/progress/` に受入条件ごとの結果、実行したコマンド、未確認事項（Tauri側、実データのない画面など）を残す。

## 終わるとき

受入条件を満たしたら終える。「さらに整えられる」を続ける理由にしない。表示・操作・互換性が変わる発見があれば、実装を進めずユーザーへ選択肢を示す。
