# ADR 0020: 固定版の工程定義とRun間の進行

状態: 採用。Issue #20、Scope revision 1。

RunDefinitionとWorkflowDefinitionはJSONを共通形式とし、GUI・ファイル・HTTP・MCPで同じ固定版を扱う。保存した下書き、静的検証の結果、採用版、実際の工程実行を別の記録にする。閲覧・保存・検証・採用ではRunを作らない。

GUIの項目編集にはjsonc-parserの文字位置による編集を使う。変更していないJSON値をJavaScriptの浮動小数点数へ変換せず、APIへUTF-8文字列で渡す。[公式資料](https://github.com/microsoft/node-jsonc-parser)のparseTree・modify・applyEditsを用いる。サーバー側ではRawMessageとPostgreSQLのjsonbを使う。

工程の正本はPostgreSQLに置き、既存の共有CAS・receipt・権限とRunを使う。新しいワークフローSDKやサービスは追加しない。進行中の実行と現在のノードを索引で取得し、Workspace全体のContextや履歴を巡回しない。定義一覧とノード一覧は本文を除いたページで取得する。

前段の結果条件、必須合流、人の判断、明示した戻り先で進行する。出力中の文章は遷移の指示にしない。入力は指定した出力・派生結果のキーや配列位置だけを解決し、プレビューと確定入力に同じ処理を使う。実行意図と新Run IDを先に保存してからRunを作成・割当する。再試行は以前のRunに関連付けた新Runとし、過去の試行と判断を保持する。

並列数と任意の実行回数・時間・費用の予算は定義に明示する。戻り先を持つ工程には有限のRun数を必須とする。費用は選んだ評価方式と通貨だけを使い、未観測・別通貨・古くなった評価を0にしない。予算は追加開始を止める条件であり、開始済みCLIの消費上限を保証しない。利用量の新しい取得経路は#24が担当する。

定義やContextの編集は進行中の採用版を変えない。明示適用の前に影響する未開始ノードと失効する判断を示す。未開始のRunを置き換える場合は以前の割当から新しく開始できなくし、開始済み入力を編集しない。回答者は工程を編集できるメンバーとする。回答で実行権限を付与せず、後続前にも元の依頼者の現在の権限を確認する。

CI観測は既存のGitHub観測接続で対象を読んだ事実を、サーバー由来の共通Run入力・結果に記録する。観測commandの終了と外部CIの判定を分け、CIの起動要求を出さない。明示した外部操作には固定commit・必須判断・条件付き操作の能力と実際の引数を要求する。割当時とネイティブRunnerの入力取得直前にも確認し、対象が変われば開始させない。接続先の保護規則を迂回する権限は追加しない。

工程のexportは固定した実行位置でページを読み、定義・採用・判断・試行・各Runの固定記録をNDJSONへ出す。未観測や未取得を保持し、権限の失効や欠落を省略して完了扱いにしない。ネイティブは既存のRunと同じストリーム保存処理を使い、最後の固定版の完了印を確認する。
